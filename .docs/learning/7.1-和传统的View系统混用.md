# 7.1 和传统的 View 系统混用

> "当 Compose 遇上传统 View，就像是一场跨时代的相亲：年轻潮流的 Compose 和经验丰富的 View
> 系统需要找到共处的方式。别担心，这不是'相爱相杀'，而是'相辅相成'！让我们来当一回'红娘'，促成这段'姻缘'
> 吧！" 💞

## 概念介绍

在 Android 开发的演进过程中，我们见证了从传统的 View 系统到现代的 Jetpack Compose 声明式 UI
框架的转变。然而，完全迁移到
Compose 可能需要时间，特别是对于已有的大型项目。此外，某些功能可能仍然需要依赖传统 View
系统的特性或第三方库。因此，Android
提供了在两个 UI 系统之间无缝集成的能力，让开发者可以逐步迁移或混合使用这两种技术。

Jetpack Compose 和传统 View 系统的互操作性主要体现在两个方向：

1. **在 View 系统中嵌入 Compose UI**：通过 `ComposeView` 或 `AndroidComposeView` 等容器，可以在传统的
   XML 布局或 View
   层次结构中嵌入 Compose UI 组件。

2. **在 Compose 中嵌入传统 View**：通过 `AndroidView` 组合函数，可以在 Compose UI 中嵌入传统的 Android
   View 组件。

这种双向互操作性使得开发者可以采用渐进式迁移策略，逐步将应用从传统 View 系统迁移到
Compose，同时保持应用的功能完整性和用户体验的一致性。

## 知识要点

- Compose 与 View 系统的基本互操作原理
- 在 View 系统中嵌入 Compose UI 的方法：
    - 使用 `ComposeView`

    - 在 Fragment 中使用 Compose

    - 使用 `AndroidView` 组合函数
    - 处理 View 的生命周期
    - 更新 View 的状态
- 在混合环境中共享数据和状态
- 处理输入事件和焦点
- 主题和样式的统一
- 动画和过渡效果的协调
- 性能优化和内存管理
- 无障碍功能的一致性
- 测试混合 UI 的策略
- 渐进式迁移的最佳实践

```kotlin
fun ComposeWithTraditionalView() {

                    text = "传统 Android 按钮"
                    setOnClickListener {
                        Toast.makeText(context, "点击了传统按钮", Toast.LENGTH_SHORT).show()
                    }
                }
            },
            // 可选：更新 View
            update = { view ->
                // 在 Compose 重组时更新 View
                (view as Button).text = "更新后的传统按钮"
            }
        )

        Spacer(modifier = Modifier.height(16.dp))

        // 嵌入自定义 View
        AndroidView(
            factory = { context ->
                // 创建自定义 View
                CustomView(context).apply {
                    setColor(Color.RED)
                }
            },
            modifier = Modifier
                .size(200.dp)
                .border(2.dp, androidx.compose.ui.graphics.Color.Gray)
        )
    }
}

// 自定义 View 示例
class CustomView(context: Context) : View(context) {
    private var color = android.graphics.Color.BLUE
    private val paint = Paint().apply {
        style = Paint.Style.FILL
    }

    fun setColor(@ColorInt color: Int) {
        this.color = color
        paint.color = color
        invalidate()
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        val centerX = width / 2f
        val centerY = height / 2f
        val radius = minOf(width, height) / 3f

        canvas.drawCircle(centerX, centerY, radius, paint)
    }
}
```

### 1. 在 Compose 中使用复杂的传统 View 组件

下面是一个在 Compose 中嵌入 `MapView` 并与之交互的示例：

```kotlin
@Composable
fun MapViewInCompose() {
    // 记住 MapView 的生命周期观察者
    val mapLifecycleObserver = rememberMapLifecycleObserver()

    // 使用 DisposableEffect 处理生命周期
    DisposableEffect(Unit) {
        mapLifecycleObserver.onCreate()
        onDispose {
            mapLifecycleObserver.onDestroy()
        }
    }

    Column(
        modifier = Modifier.fillMaxSize()
    ) {
        // 地图控制按钮
        Row(
            modifier = Modifier
                .fillMaxWidth()
                .padding(8.dp),
            horizontalArrangement = Arrangement.SpaceEvenly
        ) {
            Button(onClick = { mapLifecycleObserver.zoomIn() }) {
                Text("放大")
            }

            Button(onClick = { mapLifecycleObserver.zoomOut() }) {
                Text("缩小")
            }

            Button(onClick = { mapLifecycleObserver.resetCamera() }) {
                Text("重置")
            }
        }

        // 嵌入 MapView
        AndroidView(
            factory = { context ->
                MapView(context).apply {
                    // 初始化地图
                    mapLifecycleObserver.mapView = this
                    getMapAsync(mapLifecycleObserver)

                    // 设置地图属性
                    this.onCreate(Bundle())
                }
            },
            modifier = Modifier
                .fillMaxWidth()
                .weight(1f),
            // 更新地图
            update = { mapView ->
                // 可以在这里更新地图的属性
            }
        )
    }
}

// 地图生命周期观察者
@Composable
fun rememberMapLifecycleObserver(): MapLifecycleObserver {
    val context = LocalContext.current
    return remember {
        MapLifecycleObserver(context)
    }
}

// 地图生命周期管理类
class MapLifecycleObserver(private val context: Context) : OnMapReadyCallback {
    var mapView: MapView? = null
    private var googleMap: GoogleMap? = null

    fun onCreate() {
        mapView?.onCreate(Bundle())
    }

    fun onStart() {
        mapView?.onStart()
    }

    fun onResume() {
        mapView?.onResume()
    }

    fun onPause() {
        mapView?.onPause()
    }

    fun onStop() {
        mapView?.onStop()
    }

    fun onDestroy() {
        mapView?.onDestroy()
    }

    fun onLowMemory() {
        mapView?.onLowMemory()
    }

    override fun onMapReady(map: GoogleMap) {
        googleMap = map

        // 配置地图
        googleMap?.apply {
            uiSettings.isZoomControlsEnabled = true
            moveCamera(CameraUpdateFactory.newLatLngZoom(
                LatLng(39.9042, 116.4074), // 北京坐标
                10f
            ))
        }
    }

    // 地图控制方法
    fun zoomIn() {
        googleMap?.animateCamera(CameraUpdateFactory.zoomIn())
    }

    fun zoomOut() {
        googleMap?.animateCamera(CameraUpdateFactory.zoomOut())
    }

    fun resetCamera() {
        googleMap?.moveCamera(CameraUpdateFactory.newLatLngZoom(
            LatLng(39.9042, 116.4074),
            10f
        ))
    }
}
```

### 2. 在 View 系统中使用 Compose 状态和 ViewModel

下面是一个展示如何在 View 系统和 Compose 之间共享状态和 ViewModel 的示例：

```kotlin
// 共享 ViewModel
class SharedViewModel : ViewModel() {
    // 使用 MutableStateFlow 作为可观察状态
    private val _counter = MutableStateFlow(0)
    val counter: StateFlow<Int> = _counter

    // 使用 Compose 的 MutableState
    val composeCounter = mutableStateOf(0)

    fun incrementCounter() {
        _counter.value++
        composeCounter.value++
    }

    fun resetCounter() {
        _counter.value = 0
        composeCounter.value = 0
    }
}

// 在传统 Activity 中使用
class MixedStateActivity : AppCompatActivity() {
    private val viewModel: SharedViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_mixed_state)

        // 传统 View 按钮
        val incrementButton = findViewById<Button>(R.id.increment_button)
        val resetButton = findViewById<Button>(R.id.reset_button)
        val counterText = findViewById<TextView>(R.id.counter_text)

        // 设置点击监听器
        incrementButton.setOnClickListener {
            viewModel.incrementCounter()
        }

        resetButton.setOnClickListener {
            viewModel.resetCounter()
        }

        // 观察 StateFlow
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.counter.collect { count ->
                    counterText.text = "计数: $count"
                }
            }
        }

        // 设置 ComposeView
        findViewById<ComposeView>(R.id.compose_counter).setContent {
            MyAppTheme {
                ComposeCounter(viewModel)
            }
        }
    }
}

// Compose UI 组件
```

### 3. 在 Compose 中使用传统的 RecyclerView

下面是一个在 Compose 中嵌入和控制 RecyclerView 的示例：

```kotlin
@Composable
fun RecyclerViewInCompose() {
    // 准备数据
    val items = remember {
        List(50) { index -> "Item ${index + 1}" }
    }

    // 记住适配器
    val adapter = rememberRecyclerViewAdapter(items)

    Column(
        modifier = Modifier.fillMaxSize()
    ) {
        Text(
            text = "RecyclerView in Compose",
            style = MaterialTheme.typography.headlineMedium,
            modifier = Modifier.padding(16.dp)
        )

        // 控制按钮
        Row(
            modifier = Modifier
                .fillMaxWidth()
                .padding(horizontal = 16.dp),
            horizontalArrangement = Arrangement.SpaceEvenly
        ) {
            Button(onClick = { adapter.addItem("New Item ${(Math.random() * 1000).toInt()}") }) {
                Text("添加项目")
            }

            Button(
                onClick = { 
                    if (adapter.itemCount > 0) {
                        adapter.removeItem(0)
                    }
                }
            ) {
                Text("删除首项")
            }

            Button(onClick = { adapter.shuffleItems() }) {
                Text("打乱顺序")
            }
        }

        // 嵌入 RecyclerView
        AndroidView(
            factory = { context ->
                RecyclerView(context).apply {
                    layoutManager = LinearLayoutManager(context)
                    this.adapter = adapter

                    // 添加分割线
                    addItemDecoration(
                        DividerItemDecoration(context, DividerItemDecoration.VERTICAL)
                    )
                }
            },
            modifier = Modifier
                .fillMaxWidth()
                .weight(1f)
        )
    }
}

// 自定义适配器
class CustomAdapter : RecyclerView.Adapter<CustomAdapter.ViewHolder>() {
    private val items = mutableListOf<String>()

    class ViewHolder(val textView: TextView) : RecyclerView.ViewHolder(textView)

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ViewHolder {
        val textView = TextView(parent.context).apply {
            layoutParams = ViewGroup.LayoutParams(
                ViewGroup.LayoutParams.MATCH_PARENT,
                ViewGroup.LayoutParams.WRAP_CONTENT
            )
            setPadding(32, 32, 32, 32)
            textSize = 18f
        }
        return ViewHolder(textView)
    }

    override fun onBindViewHolder(holder: ViewHolder, position: Int) {
        holder.textView.text = items[position]
    }

    override fun getItemCount() = items.size

    fun setItems(newItems: List<String>) {
        items.clear()
        items.addAll(newItems)
        notifyDataSetChanged()
    }

    fun addItem(item: String) {
        items.add(item)
        notifyItemInserted(items.size - 1)
    }

    fun removeItem(position: Int) {
        if (position in items.indices) {
            items.removeAt(position)
            notifyItemRemoved(position)
        }
    }

    fun shuffleItems() {
        val shuffled = items.shuffled()
        items.clear()
        items.addAll(shuffled)
        notifyDataSetChanged()
    }
}

// 记住适配器实例
@Composable
fun rememberRecyclerViewAdapter(items: List<String>): CustomAdapter {
    return remember {
        CustomAdapter().apply {
            setItems(items)
        }
    }
}
```

## 常见问题

### 1. 如何处理 Compose 和 View 系统之间的主题一致性？

**回答**：确保 Compose 和传统 View 系统之间的主题一致性是混合 UI 开发中的重要挑战。以下是几种处理方法：

1. **创建统一的主题资源**：
   在 `res/values/colors.xml` 和 `res/values/styles.xml` 中定义共享的颜色和样式资源，然后在 Compose
   主题中引用这些资源。

   ```xml
   <!-- colors.xml -->
   <resources>
       <color name="primary">#6200EE</color>
       <color name="primaryDark">#3700B3</color>
       <color name="secondary">#03DAC6</color>
   </resources>
   ```

   ```kotlin
   // Compose 主题
   @Composable
   fun MyAppTheme(content: @Composable () -> Unit) {
       val colors = lightColors(
           primary = colorResource(id = R.color.primary),
           primaryVariant = colorResource(id = R.color.primaryDark),
           secondary = colorResource(id = R.color.secondary)
       )

       MaterialTheme(
           colors = colors,
           typography = Typography(),
           shapes = Shapes(),
           content = content
       )
   }
   ```

2. **使用 Material Components 主题**：
   对于传统 View，使用 Material Components 主题，这样可以更容易地与 Compose 的 Material 主题保持一致。

   ```xml
   <!-- styles.xml -->
   <style name="Theme.MyApp" parent="Theme.MaterialComponents.Light.NoActionBar">
       <item name="colorPrimary">@color/primary</item>
       <item name="colorPrimaryDark">@color/primaryDark</item>
       <item name="colorAccent">@color/secondary</item>
   </style>
   ```

3. **创建主题适配器**：
   使用 Compose Material 主题适配器库，可以从当前的 AppCompat 或 Material Components 主题中提取颜色和排版设置。

   ```kotlin
   // 添加依赖
   // implementation "com.google.accompanist:accompanist-themeadapter-material:x.x.x"

   // 在 Compose 中使用
   @Composable
   fun MyComposeContent() {
       // 从当前 Activity 的主题创建 Compose 主题
       MaterialThemeFromMdcTheme {
           // 你的 Compose UI
       }
   }
   ```

4. **动态主题切换**：
   实现一个主题管理器，可以同时更新 Compose 和传统 View 的主题。

   ```kotlin
   class ThemeManager(private val activity: Activity) {
       fun setDarkMode(isDark: Boolean) {
           // 更新 AppCompat 主题
           activity.setTheme(if (isDark) R.style.Theme_MyApp_Dark else R.style.Theme_MyApp_Light)

           // 更新 Compose 主题（通过状态更新触发重组）
           isDarkMode.value = isDark
       }
   }

   // 在 Compose 中使用
   val isDarkMode = remember { mutableStateOf(false) }

   MyAppTheme(darkTheme = isDarkMode.value) {
       // 你的 Compose UI
   }
   ```

5. **使用 Context 主题属性**：
   在 Compose 中，可以从当前 Context 中提取主题属性。

   ```kotlin
   @Composable
   fun ThemedText(text: String) {
       val context = LocalContext.current
       val textAppearance = remember {
           context.obtainStyledAttributes(
               intArrayOf(android.R.attr.textAppearanceBody1)
           ).use { it.getResourceId(0, 0) }
       }

       Text(
           text = text,
           style = TextStyle(
               fontSize = with(LocalDensity.current) {
                   context.resources.getDimension(textAppearance).toSp()
               }
           )
       )
   }
   ```

### 2. 如何在混合 UI 中处理生命周期和内存管理？

**回答**：在混合 UI 中处理生命周期和内存管理需要特别注意以下几点：

1. **使用 `DisposableEffect` 管理 View 生命周期**：
   当在 Compose 中嵌入传统 View 时，使用 `DisposableEffect` 来处理 View 的生命周期事件。

   ```kotlin
   @Composable
   fun VideoPlayerView() {
       val context = LocalContext.current
       val lifecycleOwner = LocalLifecycleOwner.current

       AndroidView(
           factory = { ctx ->
               VideoPlayerView(ctx).apply {
                   // 初始化播放器
               }
           }
       )

       // 处理生命周期
       DisposableEffect(lifecycleOwner) {
           val observer = LifecycleEventObserver { _, event ->
               when (event) {
                   Lifecycle.Event.ON_RESUME -> {
                       // 恢复播放
                   }
                   Lifecycle.Event.ON_PAUSE -> {
                       // 暂停播放
                   }
                   Lifecycle.Event.ON_DESTROY -> {
                       // 释放资源
                   }
                   else -> {}
               }
           }

           lifecycleOwner.lifecycle.addObserver(observer)

           onDispose {
               lifecycleOwner.lifecycle.removeObserver(observer)
               // 清理资源
           }
       }
   }
   ```

2. **使用 `remember` 和 `rememberSaveable` 缓存实例**：
   使用 `remember` 缓存不需要跨配置更改保存的实例，使用 `rememberSaveable` 缓存需要在配置更改后恢复的实例。

   ```kotlin
   @Composable
   fun RememberExample() {
       // 普通缓存，配置更改时会丢失
       val normalInstance = remember { ExpensiveObject() }

       // 可保存缓存，配置更改后会恢复
       val savableInstance = rememberSaveable { SaveableObject() }
   }
   ```

3. **使用 `rememberUpdatedState` 处理闭包捕获**：
   当在 `DisposableEffect` 或其他效应中捕获可能变化的值时，使用 `rememberUpdatedState` 确保始终使用最新值。

   ```kotlin
   @Composable
   fun UpdatingCallback(callback: () -> Unit) {
       // 记住最新的回调
       val latestCallback = rememberUpdatedState(callback)

       DisposableEffect(Unit) {
           val task = object : Runnable {
               override fun run() {
                   // 始终使用最新的回调
                   latestCallback.value()
               }
           }

           // 启动任务
           val handler = Handler(Looper.getMainLooper())
           handler.post(task)

           onDispose {
               handler.removeCallbacks(task)
           }
       }
   }
   ```

4. **避免内存泄漏**：
   在 Compose 中嵌入传统 View 时，要特别注意避免内存泄漏。

   ```kotlin
   // 不好的做法：可能导致内存泄漏
   AndroidView(
       factory = { context ->
           CustomView(context).apply {
               setListener(object : CustomListener {
                   override fun onEvent() {
                       // 这里可能捕获外部的 Composable 作用域
                   }
               })
           }
       }
   )

   // 好的做法：使用 update 参数更新监听器
   AndroidView(
       factory = { context ->
           CustomView(context)
       },
       update = { view ->
           view.setListener(object : CustomListener {
               override fun onEvent() {
                   // 每次重组时更新监听器
               }
           })
       }
   )
   ```

5. **使用 `produceState` 桥接异步数据**：
   使用 `produceState` 将传统的异步数据源转换为 Compose 状态。

   ```kotlin
   @Composable
   fun AsyncDataBridge(viewModel: TraditionalViewModel) {
       // 将传统异步数据转换为 Compose 状态
       val data by produceState<List<Item>>(initialValue = emptyList()) {
           val observer = Observer<List<Item>> { newData ->
               value = newData
           }

           viewModel.data.observeForever(observer)

           onDispose {
               viewModel.data.removeObserver(observer)
           }
       }

       // 使用转换后的数据
       LazyColumn {
           items(data) { item ->
               Text(item.name)
           }
       }
   }
   ```

### 3. 如何处理 Compose 和 View 系统之间的输入事件和焦点？

**回答**：处理 Compose 和 View 系统之间的输入事件和焦点需要注意以下几点：

1. **焦点管理**：
   在混合 UI 中，焦点可能需要在 Compose 和传统 View 之间切换。

   ```kotlin
   // 在 Compose 中请求焦点
   val focusRequester = remember { FocusRequester() }

   TextField(
       value = text,
       onValueChange = { text = it },
       modifier = Modifier
           .focusRequester(focusRequester)
           .focusable()
   )

   // 请求焦点
   LaunchedEffect(Unit) {
       focusRequester.requestFocus()
   }

   // 在传统 View 中请求焦点
   AndroidView(
       factory = { context ->
           EditText(context).apply {
               // 请求焦点
               post { requestFocus() }
           }
       }
   )
   ```

2. **输入事件传递**：
   确保输入事件能够正确地在两个系统之间传递。

   ```kotlin
   // 在 Compose 中处理按键事件
   Box(
       modifier = Modifier
           .fillMaxSize()
           .onKeyEvent { keyEvent ->
               // 处理按键事件
               when (keyEvent.key) {
                   Key.Enter -> {
                       // 处理回车键
                       true // 消费事件
                   }
                   else -> false // 不消费事件
               }
           }
   ) {
       // 内容
   }

   // 在传统 View 中处理按键事件
   AndroidView(
       factory = { context ->
           View(context).apply {
               isFocusable = true
               isFocusableInTouchMode = true

               setOnKeyListener { _, keyCode, event ->
                   when (keyCode) {
                       KeyEvent.KEYCODE_ENTER -> {
                           // 处理回车键
                           true // 消费事件
                       }
                       else -> false // 不消费事件
                   }
               }
           }
       }
   )
   ```

3. **触摸事件拦截**：
   在某些情况下，可能需要拦截触摸事件以防止它们传递到底层 View。

   ```kotlin
   // 在 Compose 中拦截触摸事件
   Box(
       modifier = Modifier
           .fillMaxSize()
           .pointerInput(Unit) {
               awaitPointerEventScope {
                   while (true) {
                       val event = awaitPointerEvent()
                       // 消费所有触摸事件
                       event.changes.forEach { it.consume() }
                   }
               }
           }
   ) {
       // 内容
   }

   // 在传统 View 中拦截触摸事件
   class InterceptTouchView(context: Context) : FrameLayout(context) {
       override fun onInterceptTouchEvent(ev: MotionEvent): Boolean {
           // 拦截所有触摸事件
           return true
       }
   }

   // 使用拦截 View
   AndroidView(
       factory = { context ->
           InterceptTouchView(context)
       }
   )
   ```

4. **手势冲突处理**：
   当 Compose 和传统 View 都需要处理手势时，可能会发生冲突。

   ```kotlin
   // 在 Compose 中处理手势冲突
   Box(
       modifier = Modifier
           .fillMaxSize()
           // 添加优先级较低的拖动手势
           .draggable(
               state = rememberDraggableState { /* 处理拖动 */ },
               orientation = Orientation.Vertical,
               startDragImmediately = false // 不立即开始拖动
           )
   ) {
       // 嵌入可滚动的传统 View
       AndroidView(
           factory = { context ->
               RecyclerView(context).apply {
                   // 配置 RecyclerView
               }
           }
       )
   }
   ```

5. **焦点顺序控制**：
   在表单或其他需要按特定顺序切换焦点的 UI 中，可能需要控制焦点顺序。

   ```kotlin
   // 在 Compose 中控制焦点顺序
   val (field1, field2, field3) = remember { FocusRequester.createRefs() }

   Column {
       TextField(
           value = text1,
           onValueChange = { text1 = it },
           modifier = Modifier
               .focusRequester(field1)
               .onKeyEvent {
                   if (it.key == Key.Tab) {
                       field2.requestFocus()
                       true
                   } else false
               }
       )

       TextField(
           value = text2,
           onValueChange = { text2 = it },
           modifier = Modifier
               .focusRequester(field2)
               .onKeyEvent {
                   if (it.key == Key.Tab) {
                       field3.requestFocus()
                       true
                   } else false
               }
       )

       // 嵌入传统 EditText
       AndroidView(
           factory = { context ->
               EditText(context).apply {
                   // 设置下一个焦点 ID
                   nextFocusForwardId = R.id.next_field
               }
           },
           modifier = Modifier.focusRequester(field3)
       )
   }
   ```

### 4. 如何优化混合 UI 的性能？

**回答**：优化混合 UI 的性能需要注意以下几点：

1. **减少 View 和 Compose 之间的边界交叉**：
   每次跨越 View 和 Compose 边界都会带来额外的性能开销，因此应尽量减少边界交叉次数。

   ```kotlin
   // 不好的做法：多次交叉边界
   Column {
       AndroidView(factory = { context -> TextView(context) })
       Text("Compose Text")
       AndroidView(factory = { context -> Button(context) })
       Button(onClick = {}) { Text("Compose Button") }
   }

   // 好的做法：分组相同类型的 UI
   Column {
       // View 组
       AndroidView(factory = { context ->
           LinearLayout(context).apply {
               orientation = LinearLayout.VERTICAL
               addView(TextView(context))
               addView(Button(context))
           }
       })

       // Compose 组
       Column {
           Text("Compose Text")
           Button(onClick = {}) { Text("Compose Button") }
       }
   }
   ```

2. **延迟创建复杂 View**：
   对于复杂的传统 View，可以使用延迟创建策略，只在需要时才创建。

   ```kotlin
   var showComplexView by remember { mutableStateOf(false) }

   Column {
       Button(onClick = { showComplexView = !showComplexView }) {
           Text(if (showComplexView) "隐藏" else "显示")
       }

       if (showComplexView) {
           AndroidView(
               factory = { context ->
                   // 创建复杂 View
                   ComplexView(context)
               }
           )
       }
   }
   ```

3. **使用 `key` 避免不必要的重建**：
   当 Compose 重组时，使用 `key` 参数可以避免不必要地重建 AndroidView。

   ```kotlin
   // 使用 key 避免重建
   val viewKey = remember { Object() }

   AndroidView(
       factory = { context ->
           // 创建昂贵的 View
           ExpensiveView(context)
       },
       modifier = Modifier.fillMaxWidth(),
       // 使用稳定的 key
       key = viewKey
   )
   ```

4. **优化 `update` 回调**：
   在 `AndroidView` 的 `update` 回调中，只更新必要的属性，避免不必要的操作。

   ```kotlin
   // 不好的做法：每次重组都完全重新配置
   AndroidView(
       factory = { context -> RecyclerView(context) },
       update = { recyclerView ->
           // 每次重组都重新创建适配器和布局管理器
           recyclerView.layoutManager = LinearLayoutManager(recyclerView.context)
           recyclerView.adapter = MyAdapter()
       }
   )

   // 好的做法：只更新必要的部分
   val adapter = remember { MyAdapter() }

   AndroidView(
       factory = { context ->
           RecyclerView(context).apply {
               // 在 factory 中进行一次性设置
               layoutManager = LinearLayoutManager(context)
               this.adapter = adapter
           }
       },
       update = { recyclerView ->
           // 只更新数据
           (recyclerView.adapter as MyAdapter).submitList(newItems)
       }
   )
   ```

5. **使用 `LaunchedEffect` 处理副作用**：
   对于可能导致 UI 卡顿的操作，使用 `LaunchedEffect` 将其移至协程中执行。

   ```kotlin
   @Composable
   fun HeavyOperationExample() {
       var result by remember { mutableStateOf<Result<Data>>(Result.Loading) }

       // 在协程中执行耗时操作
       LaunchedEffect(Unit) {
           result = try {
               withContext(Dispatchers.IO) {
                   // 执行耗时操作
                   val data = loadHeavyData()
                   Result.Success(data)
               }
           } catch (e: Exception) {
               Result.Error(e)
           }
       }

       // 根据结果显示 UI
       when (val res = result) {
           is Result.Loading -> LoadingIndicator()
           is Result.Success -> DataView(res.data)
           is Result.Error -> ErrorView(res.error)
       }
   }
   ```

6. **使用 `Modifier.composed` 优化复杂修饰符**：
   对于需要在 Compose 和传统 View 之间共享的复杂修饰符逻辑，可以使用 `Modifier.composed`。

   ```kotlin
   // 创建可重用的修饰符
   fun Modifier.customEffect(param: Int) = composed {
       // 在这里可以使用 Compose 的状态和效应
       var internalState by remember { mutableStateOf(0) }

       LaunchedEffect(param) {
           // 执行副作用
           internalState = calculateValue(param)
       }

       // 返回组合多个修饰符
       this
           .padding(internalState.dp)
           .background(if (internalState > 5) Color.Red else Color.Blue)
   }

   // 使用自定义修饰符
   Box(
       modifier = Modifier
           .fillMaxWidth()
           .customEffect(paramValue)
   )
   ```
