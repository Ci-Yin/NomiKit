# 3.5 AnimationSpec 之 KeyframesSpec

> "
>
如果说TweenSpec是公交车按站点行驶，SpringSpec是弹簧床自由跳跃，那么KeyframesSpec就是导演手中的分镜头脚本！它让你像电影导演一样，精确控制动画的每一个关键瞬间，想怎么演就怎么演！"
> 🎬

## 概念介绍

KeyframesSpec是Jetpack
Compose动画系统中最灵活、最精确的动画规格类型。与其他AnimationSpec不同，KeyframesSpec允许开发者明确定义动画在特定时间点的具体值，从而实现对动画过程的完全控制。

KeyframesSpec的核心思想是：

- 定义一系列时间点（关键帧）
- 为每个关键帧指定一个具体值
- 系统自动计算关键帧之间的过渡动画

这种方式类似于传统动画制作中的"关键帧动画"技术，动画师只需绘制关键的几帧，中间的过渡帧由系统自动生成。

KeyframesSpec特别适合以下场景：

- 需要精确控制动画在特定时间点的状态
- 创建非线性、不规则的动画路径
- 实现复杂的多阶段动画效果
- 模拟现实世界中的物理现象（如弹跳、震动等）
- 创建独特的品牌动效

与TweenSpec和SpringSpec相比，KeyframesSpec提供了更高的精度和灵活性，但也需要更多的手动配置。

## 知识要点

- **基本概念**：KeyframesSpec的工作原理和组成部分
- **关键参数**：
    - `durationMillis`：整个动画的总持续时间
    - 关键帧定义：`<value> at <timeMillis>`语法
    - 可选的`delayMillis`：动画开始前的延迟时间
- **关键帧定义方式**：如何定义关键帧及其值
- **插值计算**：关键帧之间的值如何计算
- **缓动函数**：如何为特定关键帧区间指定缓动函数
- **与其他规格的区别**：KeyframesSpec与TweenSpec、SpringSpec的比较
- **性能考虑**：使用KeyframesSpec的性能影响
- **适用场景**：何时选择KeyframesSpec而非其他动画规格

### 基本用法

```kotlin
@Composable
fun BasicKeyframesSpecExample() {
    // 创建一个状态来跟踪动画是否应该运行
    var isAnimating by remember { mutableStateOf(false) }
    
    // 使用KeyframesSpec创建动画
    val offsetY by animateDpAsState(
        targetValue = if (isAnimating) 300.dp else 0.dp,
        animationSpec = keyframes {
            durationMillis = 1000
            0.dp at 0 // 起始位置
            20.dp at 100 // 轻微上升
            -10.dp at 200 // 向上弹跳
            300.dp at 1000 // 最终位置
        },
        finishedListener = { isAnimating = false }
    )
    
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),

    ) {
        Text(
            text = "KeyframesSpec基本示例",
            style = MaterialTheme.typography.headlineMedium,
            modifier = Modifier.padding(bottom = 32.dp)
        )
        
        // 动画区域
        Box(
            modifier = Modifier
                .fillMaxWidth()
                .height(350.dp)
                .background(Color.LightGray.copy(alpha = 0.3f))
                .border(1.dp, Color.Gray),
            contentAlignment = Alignment.TopCenter
        ) {
            // 移动对象
            Box(
                modifier = Modifier
                    .offset(y = offsetY)
                    .size(50.dp)
                    .background(
                        color = Color(0xFF6200EE),
                        shape = CircleShape
                    ),

            ) {
                Text(
                    text = "🏀",
                    fontSize = 24.sp
```

### 延迟启动动画

```kotlin
@Composable
fun DelayedKeyframesExample() {
    // 创建状态来跟踪动画
    var isAnimating by remember { mutableStateOf(false) }
    
    // 使用KeyframesSpec创建带延迟的动画
    val scale by animateFloatAsState(
        targetValue = if (isAnimating) 2f else 1f,
        animationSpec = keyframes {
            durationMillis = 1000
            delayMillis = 500 // 添加500毫秒的延迟
            
            1f at 0
            1.2f at 200
            1.8f at 700
            2f at 1000
        },
        finishedListener = { isAnimating = false }
    )
    
    // 创建一个计时器来显示动画状态
    var elapsedTime by remember { mutableStateOf(0L) }
    var timerJob by remember { mutableStateOf<Job?>(null) }
    
    // 启动计时器
    LaunchedEffect(isAnimating) {
        if (isAnimating) {
            elapsedTime = 0
            timerJob?.cancel()
            timerJob = launch {
                val startTime = System.currentTimeMillis()
                while (isActive) {
                    elapsedTime = System.currentTimeMillis() - startTime
                    delay(16) // 约60fps的更新率
                }
            }
        } else {
            timerJob?.cancel()
        }
    }
    
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        Text(
            text = "延迟启动动画",
            style = MaterialTheme.typography.headlineMedium,
            modifier = Modifier.padding(bottom = 32.dp)
        )
        
        // 计时器显示
        Text(
            text = "经过时间: ${elapsedTime}ms",
            style = MaterialTheme.typography.titleMedium,
            color = if (elapsedTime < 500) Color.Red else Color.Green
```

## 常见问题

### 1. KeyframesSpec与TweenSpec有什么区别？

**答**：KeyframesSpec和TweenSpec的主要区别在于：

1. **控制精度**：
    - KeyframesSpec：允许精确控制动画在特定时间点的具体值
    - TweenSpec：只能指定起点、终点和整体缓动函数

2. **复杂度**：
    - KeyframesSpec：可以创建复杂的非线性动画路径
    - TweenSpec：只能创建从起点到终点的平滑过渡

3. **缓动函数应用**：
    - KeyframesSpec：可以为不同的关键帧区间指定不同的缓动函数
    - TweenSpec：只能为整个动画应用一个缓动函数

4. **使用场景**：
    - KeyframesSpec：适合需要精确控制的复杂动画，如弹跳、震动等
    - TweenSpec：适合简单的从A到B的平滑过渡

5. **配置复杂性**：
    - KeyframesSpec：需要手动指定多个时间点和值
    - TweenSpec：配置简单，只需指定持续时间和缓动函数

选择哪一个取决于你的具体需求：如果需要简单的平滑过渡，使用TweenSpec；如果需要精确控制动画路径，使用KeyframesSpec。

### 2. 如何在KeyframesSpec中实现不同关键帧之间的不同缓动效果？

**答**：在KeyframesSpec中实现不同关键帧之间的不同缓动效果，可以使用`with`关键字为每个关键帧指定缓动函数：

```kotlin
keyframes {
    durationMillis = 1000
    
    0f at 0 with LinearEasing // 起始点
    0.5f at 300 with FastOutSlowInEasing // 0-300ms使用FastOutSlowInEasing
    0.7f at 700 with LinearEasing // 300-700ms使用LinearEasing
    1f at 1000 with FastOutLinearInEasing // 700-1000ms使用FastOutLinearInEasing
}
```

关键点说明：

1. **语法格式**：`<value> at <timeMillis> with <EasingFunction>`

2. **缓动函数应用范围**：
    - 缓动函数应用于当前关键帧到下一个关键帧之间的插值
    - 最后一个关键帧的缓动函数不会被使用

3. **可用的缓动函数**：
    - `LinearEasing`：线性缓动，匀速变化
    - `FastOutSlowInEasing`：快出慢进，类似标准减速
    - `FastOutLinearInEasing`：快出线性进，开始快结束匀速
    - `LinearOutSlowInEasing`：线性出慢进，开始匀速结束慢
    - 自定义缓动函数：可以实现CubicBezierEasing或其他自定义缓动

4. **注意事项**：
    - 如果省略缓动函数，系统会使用默认的FastOutSlowInEasing
    - 缓动函数只影响关键帧之间的插值，不会改变关键帧本身的值
    - 合理选择缓动函数可以显著提升动画的自然感和专业性

通过为不同的关键帧区间指定不同的缓动函数，可以创建更加复杂和精细的动画效果。

### 3. KeyframesSpec的性能如何？使用时需要注意什么？

**答**：KeyframesSpec的性能考虑和注意事项：

1. **性能特点**：
    - KeyframesSpec通常比其他AnimationSpec需要更多的计算资源
    - 关键帧数量越多，计算开销越大
    - 在大多数现代设备上，合理使用KeyframesSpec不会造成明显性能问题

2. **性能优化建议**：
    - **限制关键帧数量**：只在必要的时间点定义关键帧，避免过度定义
    - **避免过短的动画**：非常短的动画可能不值得使用复杂的KeyframesSpec
    - **避免同时运行太多KeyframesSpec动画**：特别是在低端设备上
    - **考虑使用更简单的替代方案**：对于简单动画，考虑使用TweenSpec或SpringSpec

3. **内存考虑**：
    - KeyframesSpec在内部存储所有关键帧信息，关键帧越多，内存占用越大
    - 对于重复使用的KeyframesSpec，考虑将其定义为常量或使用remember缓存

4. **调试与测试**：
    - 在低端设备上测试动画性能
    - 使用Android Studio的Profiler监控动画执行期间的CPU和内存使用
    - 如果发现性能问题，考虑简化关键帧或使用其他动画规格

5. **适用场景权衡**：
    - 对于需要精确控制的品牌动效，KeyframesSpec的价值通常超过其性能成本
    - 对于频繁执行的小动画，可能需要权衡精确控制和性能之间的关系

总体而言，KeyframesSpec在合理使用的情况下性能是可接受的，但开发者应该意识到它比其他动画规格更复杂，并在必要时进行优化。

### 4. 如何创建一个在特定关键帧暂停的动画？

**答**：创建在特定关键帧暂停的动画有几种方法：

1. **使用关键帧时间间隔**：
    - 在需要暂停的地方，连续定义两个相同值但时间不同的关键帧

   ```kotlin
   keyframes {
       durationMillis = 2000
       
       0f at 0 // 起始值
       0.5f at 500 // 到达中间值
       0.5f at 1500 // 在中间值暂停1000毫秒
       1f at 2000 // 最终值
   }
   ```

2. **使用多个动画序列**：
    - 使用Animatable和协程创建更复杂的控制

   ```kotlin
   LaunchedEffect(key1) {
       val animatable = Animatable(0f)
       
       // 第一段动画
       animatable.animateTo(
           targetValue = 0.5f,
           animationSpec = tween(500)
       )
       
       // 暂停
       delay(1000)
       
       // 第二段动画
       animatable.animateTo(
           targetValue = 1f,
           animationSpec = tween(500)
       )
   }
   ```

3. **使用状态控制**：
    - 使用状态变量控制动画的不同阶段

   ```kotlin
   // 定义动画阶段
   enum class AnimationStage { First, Pause, Second }
   
   // 跟踪当前阶段
   var stage by remember { mutableStateOf(AnimationStage.First) }
   
   // 根据阶段设置目标值
   val targetValue = when(stage) {
       AnimationStage.First -> 0.5f
       AnimationStage.Pause -> 0.5f // 保持相同值
       AnimationStage.Second -> 1f
   }
   
   val progress by animateFloatAsState(
       targetValue = targetValue,
       // 使用适当的动画规格
       animationSpec = tween(500),
       // 在第一阶段完成后切换到暂停阶段
       finishedListener = {
           when(stage) {
               AnimationStage.First -> {
                   // 切换到暂停阶段
                   stage = AnimationStage.Pause
                   // 延迟后进入第二阶段
                   scope.launch {
                       delay(1000)
                       stage = AnimationStage.Second
                   }
               }
               AnimationStage.Second -> {
                   // 动画完成
               }
               else -> {}
           }
       }
   )
   ```

4. **使用KeyframesSpec的精确控制**：
    - 在暂停点前后使用不同的缓动函数

   ```kotlin
   keyframes {
       durationMillis = 2000
       
       0f at 0 with FastOutSlowInEasing
       0.5f at 500 with LinearEasing // 到达中间值
       0.5f at 1500 with LinearEasing // 保持不变（实际上是线性插值，但值相同）
       1f at 2000 // 最终值
   }
   ```

选择哪种方法取决于你的具体需求和动画复杂度。对于简单的暂停，第一种方法最直接；对于复杂的控制逻辑，第二或第三种方法提供了更多灵活性。
