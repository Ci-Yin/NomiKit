> 没有它，Row和Column可能就不知道该怎么摆放子元素了！" 🧩🔄

## 概念介绍

ParentDataModifier是Jetpack Compose中一类特殊的修饰符，它与其他修饰符有着本质的区别。大多数修饰符（如
`size`、`padding`、
`background`等）直接影响应用它们的组件本身，而ParentDataModifier则是用来影响父组件如何处理和放置子组件的。

在Compose的布局系统中，父组件负责测量和放置其子组件。ParentDataModifier允许子组件向其父组件传递额外的信息，这些信息会影响父组件对子组件的测量和放置行为。这种机制使得子组件能够在特定的布局环境中表达特殊的布局需求。

ParentDataModifier的关键特点包括：

1. **上下文相关性**：ParentDataModifier只在特定的父组件上下文中有效。例如，`weight`修饰符只在`Row`和
   `Column`中有效，而
   `align`修饰符只在`Box`中有效。

2. **数据传递机制**：它们不直接修改子组件，而是将数据传递给父组件，由父组件决定如何使用这些数据。

3. **布局影响**：它们影响的是布局阶段，特别是父组件对子组件的测量和放置过程。

4. **组合性**：与其他修饰符一样，ParentDataModifier也可以组合使用，但需要注意它们的作用域和优先级。

常见的ParentDataModifier包括：

- `weight`：在`Row`和`Column`中指定子组件的权重
- `align`：在`Box`中指定子组件的对齐方式
- `wrapContentSize`：指定内容包裹的方式
- `layoutId`：在`ConstraintLayout`中标识子组件

理解ParentDataModifier的工作原理对于创建复杂而灵活的UI布局至关重要，它是Compose布局系统强大功能的关键组成部分。

@Composable
fun LayoutIdExample() {
    Column(
        modifier = Modifier
            .fillMaxWidth()
            .padding(16.dp)
    ) {
        Text(
            text = "layoutId修饰符示例",
            style = MaterialTheme.typography.titleMedium,
            modifier = Modifier.padding(bottom = 8.dp)
        )
        
        // 创建引用
        val constraints = ConstraintSet {
            val header = createRefFor("header")
            val image = createRefFor("image")
            val title = createRefFor("title")
            val description = createRefFor("description")
            val button = createRefFor("button")
            
            // 设置约束
            constrain(header) {
                top.linkTo(parent.top)
                start.linkTo(parent.start)
                end.linkTo(parent.end)
                width = Dimension.fillToConstraints
            }
            
            constrain(image) {
                top.linkTo(header.bottom, margin = 16.dp)
                start.linkTo(parent.start)
                width = Dimension.value(100.dp)
                height = Dimension.value(100.dp)
            }
            
            constrain(title) {
                top.linkTo(image.top)
                start.linkTo(image.end, margin = 16.dp)
                end.linkTo(parent.end)
                width = Dimension.fillToConstraints
            }
            
            constrain(description) {
                top.linkTo(title.bottom, margin = 8.dp)
                start.linkTo(title.start)
                end.linkTo(parent.end)
                width = Dimension.fillToConstraints
            }
            
            constrain(button) {
                top.linkTo(description.bottom, margin = 16.dp)
                end.linkTo(parent.end)
            }
        }
        
        // 应用约束
        ConstraintLayout(
            constraintSet = constraints,
            modifier = Modifier
                .fillMaxWidth()
                .height(250.dp)
                .background(Color.LightGray, RoundedCornerShape(8.dp))
                .padding(16.dp)
        ) {
            // 头部
            Box(
                modifier = Modifier
                    .background(Color(0xFF3F51B5))
                    .height(40.dp)

// 自定义ParentDataModifier示例
// 首先定义一个自定义的ParentData类
data class CustomParentData(
    val scale: Float = 1f,
    val rotation: Float = 0f,
    val alpha: Float = 1f
)

// 创建一个自定义的ParentDataModifier
class CustomParentDataModifier(
    private val scale: Float,
    private val rotation: Float,
    private val alpha: Float
) : ParentDataModifier {
    override fun Density.modifyParentData(parentData: Any?): Any {
        return (parentData as? CustomParentData ?: CustomParentData()).copy(
            scale = scale,
            rotation = rotation,
            alpha = alpha
        )
    }
}

// 为Modifier添加扩展函数
fun Modifier.customStyle(
    scale: Float = 1f,
    rotation: Float = 0f,
    alpha: Float = 1f
) = this.then(CustomParentDataModifier(scale, rotation, alpha))

// 创建一个自定义布局来使用这个ParentDataModifier
@Composable
fun CustomParentDataLayout(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier
    ) { measurables, constraints ->
        // 测量所有子元素
        val placeables = measurables.map { measurable ->
            // 获取子元素的ParentData
            val parentData = measurable.parentData as? CustomParentData ?: CustomParentData()
            
            // 测量子元素
            measurable.measure(constraints)
        }
        
        // 计算布局的大小
        val width = placeables.maxOfOrNull { it.width } ?: 0
        val height = placeables.maxOfOrNull { it.height } ?: 0
        
        // 创建布局
        layout(width, height) {
            placeables.forEachIndexed { index, placeable ->
                // 获取子元素的ParentData
                val parentData = measurables[index].parentData as? CustomParentData ?: CustomParentData()
                
                // 计算位置
                val x = (width - placeable.width) / 2
                val y = (height - placeable.height) / 2
                
                // 放置子元素，应用自定义的变换
                placeable.placeWithLayer(x, y) {
                    scaleX = parentData.scale
                    scaleY = parentData.scale
                    rotationZ = parentData.rotation
                    alpha = parentData.alpha
                }
            }
        }
    }
}

## 常见问题

### 1. 为什么我的ParentDataModifier不起作用？

**问题**：我在组件上应用了ParentDataModifier（如`weight`或`align`），但它似乎没有任何效果。

**解答**：ParentDataModifier只在特定的父组件上下文中有效。以下是一些常见的原因和解决方案：

1. **父组件不匹配**：
    - `weight`修饰符只在`Row`和`Column`中有效
    - `align`修饰符只在`Box`中有效
    - `layoutId`修饰符只在`ConstraintLayout`中有效

   确保你在正确的父组件上下文中使用这些修饰符。

   ```kotlin
   // 错误示例：在Box中使用weight
   Box {
       Text(
           "这不会起作用",
           modifier = Modifier.weight(1f) // 在Box中不起作用
       )
   }
   
   // 正确示例：在Row中使用weight
   Row {
       Text(
           "这会正常工作",
           modifier = Modifier.weight(1f)
       )
   }
   ```

2. **修饰符顺序问题**：
   当多个ParentDataModifier应用于同一个组件时，只有最后一个对应特定父布局的修饰符会生效。

   ```kotlin
   // 在这个例子中，只有align(Alignment.BottomEnd)会生效
   Box {
       Text(
           "只有BottomEnd会生效",
           modifier = Modifier
               .align(Alignment.TopStart) // 这个会被覆盖
               .align(Alignment.BottomEnd) // 这个会生效
       )
   }
   ```

3. **嵌套布局问题**：
   ParentDataModifier只影响直接父组件，不会传递给更高层级的祖先组件。

   ```kotlin
   // 错误示例：weight不会影响外层的Row
   Row {
       Column {
           Text(
               "这不会影响外层Row的weight",
               modifier = Modifier.weight(1f) // 这只会影响Column，不会影响Row
           )
       }
   }
   
   // 正确示例：将weight应用于Column
   Row {
       Column(
           modifier = Modifier.weight(1f) // 这会正确影响Row中Column的权重
       ) {
           Text("这样就对了")
       }
   }
   ```

4. **布局约束冲突**：
   有时，其他修饰符可能会与ParentDataModifier产生冲突。例如，在使用`weight`的同时设置固定宽度。

   ```kotlin
   // 冲突示例：width和weight冲突
   Row {
       Text(
           "width会覆盖weight的效果",
           modifier = Modifier
               .width(100.dp) // 这会覆盖weight的效果
               .weight(1f)
       )
   }
   
   // 更好的做法：使用weight的fill参数
   Row {
       Text(
           "使用fill=false可以保持固有宽度",
           modifier = Modifier.weight(1f, fill = false)
       )
   }
   ```

5. **父组件的大小限制**：
   如果父组件本身大小受限，ParentDataModifier可能看起来没有效果。

   ```kotlin
   // 问题示例：父Row没有足够空间
   Box(modifier = Modifier.size(50.dp)) { // Row被限制在很小的空间内
       Row {
           Text(
               "看不到weight效果",
               modifier = Modifier.weight(1f)
           )
       }
   }
   
   // 解决方案：确保父组件有足够空间
   Box(modifier = Modifier.fillMaxWidth()) {
       Row {
           Text(
               "现在可以看到weight效果",
               modifier = Modifier.weight(1f)
           )
       }
   }
   ```

通过检查这些常见问题，你通常可以找出为什么ParentDataModifier不起作用的原因。记住，理解每个修饰符的作用域和父组件的要求是关键。

### 2. 如何在自定义布局中处理ParentDataModifier？

**问题**：我正在创建一个自定义布局，如何让它支持自定义的ParentDataModifier？

**解答**：在自定义布局中处理ParentDataModifier需要几个关键步骤：

1. **定义自定义的ParentData类**：
   首先，创建一个数据类来保存你想从子组件传递到父布局的信息。

   ```kotlin
   // 自定义ParentData类
   data class MyCustomParentData(
       val importance: Float = 1f,
       val alignment: Alignment = Alignment.Center,
       val visible: Boolean = true
   )
   ```

2. **创建ParentDataModifier实现**：
   实现ParentDataModifier接口，定义如何修改父数据。

   ```kotlin
   // 自定义ParentDataModifier
   class MyCustomParentDataModifier(
       private val importance: Float,
       private val alignment: Alignment,
       private val visible: Boolean
   ) : ParentDataModifier {
       override fun Density.modifyParentData(parentData: Any?): Any {
           return (parentData as? MyCustomParentData ?: MyCustomParentData()).copy(
               importance = importance,
               alignment = alignment,
               visible = visible
           )
       }
   }
   ```

3. **为Modifier添加扩展函数**：
   创建一个扩展函数，使修饰符易于使用。

   ```kotlin
   // Modifier扩展函数
   fun Modifier.myCustomModifier(
       importance: Float = 1f,
       alignment: Alignment = Alignment.Center,
       visible: Boolean = true
   ) = this.then(
       MyCustomParentDataModifier(
           importance = importance,
           alignment = alignment,
           visible = visible
       )
   )
   ```

4. **在自定义布局中使用ParentData**：
   在自定义布局的实现中，从Measurable中获取并使用ParentData。

   ```kotlin
   @Composable
   fun MyCustomLayout(
       modifier: Modifier = Modifier,
       content: @Composable () -> Unit
   ) {
       Layout(
           content = content,
           modifier = modifier
       ) { measurables, constraints ->
           // 根据ParentData过滤和排序measurables
           val filteredMeasurables = measurables.filter { measurable ->
               val parentData = measurable.parentData as? MyCustomParentData
                   ?: MyCustomParentData()
               parentData.visible
           }
           
           val sortedMeasurables = filteredMeasurables.sortedByDescending { measurable ->
               val parentData = measurable.parentData as? MyCustomParentData
                   ?: MyCustomParentData()
               parentData.importance
           }
           
           // 测量子元素
           val placeables = sortedMeasurables.map { measurable ->
               measurable.measure(constraints)
           }
           
           // 计算布局大小
           val width = placeables.maxOfOrNull { it.width } ?: 0
           val height = placeables.maxOfOrNull { it.height } ?: 0
           
           // 放置子元素
           layout(width, height) {
               placeables.forEachIndexed { index, placeable ->
                   // 获取对应的ParentData
                   val parentData = sortedMeasurables[index].parentData as? MyCustomParentData
                       ?: MyCustomParentData()
                   
                   // 根据alignment计算位置
                   val x = when (parentData.alignment) {
                       Alignment.Start, Alignment.TopStart, Alignment.CenterStart, Alignment.BottomStart ->
                           0
                       Alignment.End, Alignment.TopEnd, Alignment.CenterEnd, Alignment.BottomEnd ->
                           width - placeable.width
                       else -> (width - placeable.width) / 2 // Center
                   }
                   
                   val y = when (parentData.alignment) {
                       Alignment.Top, Alignment.TopStart, Alignment.TopCenter, Alignment.TopEnd ->
                           0
                       Alignment.Bottom, Alignment.BottomStart, Alignment.BottomCenter, Alignment.BottomEnd ->
                           height - placeable.height
                       else -> (height - placeable.height) / 2 // Center
                   }
                   
                   // 放置子元素
                   placeable.place(x, y)
               }
           }
       }
   }
   ```

5. **使用自定义布局和修饰符**：
   现在可以在你的应用中使用这个自定义布局和修饰符。

   ```kotlin
   @Composable
   fun CustomLayoutExample() {
       MyCustomLayout(
           modifier = Modifier
               .fillMaxWidth()
               .height(200.dp)
               .background(Color.LightGray)
       ) {
           // 高重要性，居中对齐
           Text(
               "重要内容",
               modifier = Modifier.myCustomModifier(
                   importance = 3f,
                   alignment = Alignment.Center
               )
           )
           
           // 低重要性，顶部对齐
           Text(
               "次要内容",
               modifier = Modifier.myCustomModifier(
                   importance = 1f,
                   alignment = Alignment.TopStart
               )
           )
           
           // 不可见内容
           Text(
               "这不会显示",
               modifier = Modifier.myCustomModifier(
                   visible = false
               )
           )
       }
   }
   ```

6. **处理多个ParentDataModifier**：
   如果你的布局需要处理多种类型的ParentDataModifier，可以使用类型检查和合并逻辑。

   ```kotlin
   override fun Density.modifyParentData(parentData: Any?): Any {
       // 处理不同类型的ParentData
       return when (parentData) {
           is MyCustomParentData -> parentData.copy(
               importance = importance,
               alignment = alignment,
               visible = visible
           )
           is SomeOtherParentData -> {
               // 创建一个新的MyCustomParentData，保留其他信息
               MyCustomParentData(
                   importance = importance,
                   alignment = alignment,
                   visible = visible
               )
           }
           else -> MyCustomParentData(
               importance = importance,
               alignment = alignment,
               visible = visible
           )
       }
   }
   ```

通过这些步骤，你可以创建支持自定义ParentDataModifier的布局，使你的UI组件更加灵活和可配置。记住，好的API设计应该使修饰符的行为直观且一致，并与Compose的其他部分保持一致的风格。

### 3. ParentDataModifier和普通修饰符的顺序重要吗？

**问题**：在应用多个修饰符时，ParentDataModifier和其他修饰符（如`size`、`padding`等）的顺序会影响结果吗？

**解答**：是的，修饰符的顺序非常重要，它会影响最终的布局和外观。理解修饰符的应用顺序对于创建预期的UI效果至关重要：

1. **修饰符的应用顺序**：
   修饰符从左到右（或从上到下）依次应用。每个修饰符都会修改前一个修饰符的结果，然后传递给下一个修饰符。

   ```kotlin
   // 修饰符从左到右应用
   Modifier
       .padding(16.dp)    // 首先应用
       .size(100.dp)      // 其次应用
       .background(Color.Red) // 最后应用
   ```

2. **ParentDataModifier与大小修饰符的交互**：
   ParentDataModifier（如`weight`）与大小修饰符（如`size`、`width`、`height`）的顺序会影响最终结果。

   ```kotlin
   // 示例1：weight在size之前
   Row {
       Box(
           modifier = Modifier
               .weight(1f)     // 首先应用weight
               .size(50.dp)    // 然后应用size，这会覆盖weight的宽度效果
       )
   }
   
   // 示例2：size在weight之前
   Row {
       Box(
           modifier = Modifier
               .size(50.dp)    // 首先应用size
               .weight(1f)     // 然后应用weight，这会覆盖size的宽度效果
       )
   }
   ```

3. **ParentDataModifier与padding的交互**：
   `padding`修饰符的位置会影响ParentDataModifier的行为。

   ```kotlin
   // 示例1：padding在weight之前
   Row {
       Box(
           modifier = Modifier
               .padding(16.dp)  // 首先应用padding
               .weight(1f)      // 然后应用weight，weight会影响padding后的内容
       )
   }
   
   // 示例2：weight在padding之前
   Row {
       Box(
           modifier = Modifier
               .weight(1f)      // 首先应用weight
               .padding(16.dp)  // 然后应用padding，padding不会影响weight的计算
       )
   }
   ```

4. **ParentDataModifier与background的交互**：
   `background`修饰符的位置会影响视觉效果，特别是与`padding`结合时。

   ```kotlin
   // 示例1：background在padding之前
   Box(
       modifier = Modifier
           .align(Alignment.Center)  // 首先应用align
           .background(Color.Red)    // 然后应用background
           .padding(16.dp)           // 最后应用padding，padding在红色背景内部
   )
   
   // 示例2：padding在background之前
   Box(
       modifier = Modifier
           .align(Alignment.Center)  // 首先应用align
           .padding(16.dp)           // 然后应用padding
           .background(Color.Red)    // 最后应用background，红色背景不包括padding区域
   )
   ```

5. **多个ParentDataModifier的顺序**：
   当应用多个针对同一父组件的ParentDataModifier时，只有最后一个会生效。

   ```kotlin
   // 只有BottomEnd会生效
   Box {
       Text(
           "文本",
           modifier = Modifier
               .align(Alignment.TopStart)    // 这个会被覆盖
               .align(Alignment.BottomEnd)   // 这个会生效
       )
   }
   ```

6. **不同父组件的ParentDataModifier**：
   针对不同父组件的ParentDataModifier可以共存，不会相互覆盖。

   ```kotlin
   // weight和align可以共存，因为它们针对不同的父组件
   Row {
       Box(
           modifier = Modifier.weight(1f)  // 针对Row
       ) {
           Text(
               "文本",
               modifier = Modifier.align(Alignment.Center)  // 针对Box
           )
       }
   }
   ```

7. **最佳实践**：
    - 将ParentDataModifier放在修饰符链的开始位置，除非你有特定原因需要其他顺序
    - 保持一致的修饰符顺序，提高代码可读性
    - 当遇到意外行为时，尝试调整修饰符顺序

   ```kotlin
   // 推荐的修饰符顺序
   Modifier
       .weight(1f)            // ParentDataModifier先应用
       .padding(16.dp)        // 然后是布局修饰符
       .size(100.dp)
       .background(Color.Red) // 最后是外观修饰符
       .clickable { }         // 和行为修饰符
   ```

理解修饰符的应用顺序可以帮助你更精确地控制UI的布局和外观，避免意外的行为。当你遇到布局问题时，检查修饰符的顺序通常是解决问题的第一步。

### 5. 如何处理复杂布局中的ParentDataModifier冲突？

**问题**：在复杂的嵌套布局中，我遇到了ParentDataModifier的冲突或意外行为，如何有效地处理这些情况？

**解答**：复杂布局中的ParentDataModifier冲突可能来自多个方面，以下是处理这些问题的策略：

1. **理解修饰符的作用域**：
   每个ParentDataModifier只对其直接父组件有效，不会影响更高层级的祖先组件。

   ```kotlin
   // 示例：嵌套布局中的修饰符作用域
   Row(modifier = Modifier.fillMaxWidth()) {
       // weight只影响这个Column在Row中的布局
       Column(modifier = Modifier.weight(1f)) {
           // align只影响这个Text在Box中的布局，不影响Column在Row中的布局
           Box(modifier = Modifier.fillMaxWidth()) {
               Text(
                   "文本",
                   modifier = Modifier.align(Alignment.Center)
               )
           }
       }
   }
   ```

2. **使用中间容器隔离修饰符**：
   当需要应用多个可能冲突的ParentDataModifier时，使用中间容器来隔离它们。

   ```kotlin
   // 问题：weight和align可能产生混淆
   Row {
       Text(
           "文本",
           modifier = Modifier
               .weight(1f)
               .align(Alignment.CenterVertically) // 这里可能让人困惑
       )
   }
   
   // 解决方案：使用Box作为中间容器
   Row {
       Box(
           modifier = Modifier.weight(1f),
           contentAlignment = Alignment.Center // 使用contentAlignment代替子元素的align
       ) {
           Text("文本")
       }
   }
   ```

3. **优先使用布局的内置属性**：
   许多布局组件提供了内置属性，可以替代子元素上的ParentDataModifier。

   ```kotlin
   // 不推荐：在每个子元素上使用align
   Box {
       Text(
           "文本1",
           modifier = Modifier.align(Alignment.TopStart)
       )
       Text(
           "文本2",
           modifier = Modifier.align(Alignment.Center)
       )
   }
   
   // 推荐：使用Box的contentAlignment属性
   Box(
       contentAlignment = Alignment.Center // 应用于所有子元素
   ) {
       Text("文本1")
       // 仍然可以在需要时覆盖默认对齐
       Text(
           "文本2",
           modifier = Modifier.align(Alignment.TopStart)
       )
   }
   ```

4. **使用命名修饰符提高可读性**：
   为复杂的修饰符链创建命名变量，提高代码可读性和可维护性。

   ```kotlin
   // 定义命名修饰符
   val headerModifier = Modifier
       .fillMaxWidth()
       .padding(16.dp)
   
   val contentModifier = Modifier
       .weight(1f)
       .padding(horizontal = 16.dp)
   
   val footerModifier = Modifier
       .fillMaxWidth()
       .padding(16.dp)
   
   // 在布局中使用
   Column(modifier = Modifier.fillMaxSize()) {
       Text("标题", modifier = headerModifier)
       Text("内容", modifier = contentModifier)
       Text("页脚", modifier = footerModifier)
   }
   ```

5. **创建自定义布局组合**：
   对于经常重复的复杂布局模式，创建自定义的组合函数。

   ```kotlin

           modifier = modifier.fillMaxWidth(),

       Text("中间", modifier = Modifier.weight(2f))
       Text("右侧", modifier = Modifier.weight(1f))
   }
   ```

6. **使用LayoutModifier代替ParentDataModifier**：
   在某些情况下，使用LayoutModifier（如`offset`）可能比ParentDataModifier更可预测。

   ```kotlin

       val boxSize = 50.dp
       // 居中放置
       Box(
           modifier = Modifier
               .size(boxSize)
               .offset(
                   x = (200.dp - boxSize) / 2,
                   y = (200.dp - boxSize) / 2
               )
               .background(Color.Red)
       )
   }
   ```

7. **分层处理复杂布局**：
   将复杂布局分解为多个层次，每层处理特定的布局需求。

   ```kotlin

           modifier = Modifier
               .fillMaxSize()

                   .padding(16.dp)

                   modifier = Modifier
                       .fillMaxWidth()
                       .height(56.dp)
               ) {
                   // 内容...
               }
               
               // 第四层：处理中间内容
               Box(
                   modifier = Modifier
                       .weight(1f)
                       .fillMaxWidth()
               ) {
                   // 内容...
               }
               
               // 第五层：处理底部栏
               Row(
                   modifier = Modifier
                       .fillMaxWidth()
                       .height(56.dp)
               ) {
                   // 内容...
               }
           }
       }
   }
   ```

8. **使用ConstraintLayout处理复杂关系**：
   对于非常复杂的布局关系，考虑使用ConstraintLayout，它提供了更精细的控制。

   ```kotlin

       ConstraintLayout(
           modifier = Modifier.fillMaxSize()
       ) {
           val (header, content, footer, fab) = createRefs()
           
           Text(
               "标题",
               modifier = Modifier.constrainAs(header) {
                   top.linkTo(parent.top)
                   start.linkTo(parent.start)
                   end.linkTo(parent.end)
                   width = Dimension.fillToConstraints
               }
           )
           
           Text(
               "内容",
               modifier = Modifier.constrainAs(content) {
                   top.linkTo(header.bottom)
                   bottom.linkTo(footer.top)
                   start.linkTo(parent.start)
                   end.linkTo(parent.end)
                   width = Dimension.fillToConstraints
                   height = Dimension.fillToConstraints
               }
           )
           
           Text(
               "页脚",
               modifier = Modifier.constrainAs(footer) {
                   bottom.linkTo(parent.bottom)
                   start.linkTo(parent.start)
                   end.linkTo(parent.end)
                   width = Dimension.fillToConstraints
               }
           )
           
           FloatingActionButton(
               onClick = { },
               modifier = Modifier.constrainAs(fab) {
                   bottom.linkTo(parent.bottom, margin = 16.dp)
                   end.linkTo(parent.end, margin = 16.dp)
               }
           ) {
               Icon(Icons.Default.Add, contentDescription = "添加")
           }
       }
   }
   ```

通过这些策略，你可以更有效地处理复杂布局中的ParentDataModifier冲突，创建更可维护和可预测的UI代码。记住，好的布局设计应该是清晰、模块化和可组合的，这样可以减少潜在的冲突和混淆。

@Composable
fun AdaptiveGrid(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier
    ) { measurables, constraints ->
        // 计算每行可以放置的项目数量
        val minItemWidth = 100.dp.roundToPx()
        val itemsPerRow = maxOf(1, constraints.maxWidth / minItemWidth)
        
        // 计算实际的项目宽度
        val itemWidth = constraints.maxWidth / itemsPerRow
        
        // 测量所有子元素
        val placeables = measurables.map { measurable ->
            measurable.measure(
                constraints.copy(
                    minWidth = itemWidth,
                    maxWidth = itemWidth
                )
            )
        }
        
        // 计算行数
        val rows = (placeables.size + itemsPerRow - 1) / itemsPerRow
        
        // 计算总高度
        val itemHeight = placeables.maxOfOrNull { it.height } ?: 0
        val height = minOf(
            constraints.maxHeight,
            rows * itemHeight
        )
        
        // 放置子元素
        layout(constraints.maxWidth, height) {
            var x = 0
            var y = 0
            
            placeables.forEachIndexed { index, placeable ->
                placeable.place(x, y)
                
                // 更新x坐标
                x += itemWidth
                
                // 如果到达行尾，换行
                if ((index + 1) % itemsPerRow == 0) {
                    x = 0
                    y += itemHeight
                }
            }
        }
    }
}

@Composable
fun FlowLayout(
    modifier: Modifier = Modifier,
    spacing: Dp = 0.dp,
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier
    ) { measurables, constraints ->
        val spacingPx = spacing.roundToPx()
        
        // 测量所有子元素
        val placeables = measurables.map { measurable ->
            measurable.measure(constraints.copy(minWidth = 0, minHeight = 0))
        }
        
        // 计算布局
        var xPos = 0
        var yPos = 0
        var rowHeight = 0
        
        // 第一次遍历：计算每个元素的位置
        val positions = placeables.map { placeable ->
            // 如果当前行放不下这个元素，换行
            if (xPos + placeable.width > constraints.maxWidth) {
                xPos = 0
                yPos += rowHeight + spacingPx
                rowHeight = 0
            }
            
            // 记录位置
            val position = Offset(xPos.toFloat(), yPos.toFloat())
            
            // 更新x坐标和行高
            xPos += placeable.width + spacingPx
            rowHeight = maxOf(rowHeight, placeable.height)
            
            position
        }
        
        // 计算总高度
        val height = if (placeables.isEmpty()) {
            0
        } else {
            yPos + rowHeight
        }
        
        // 创建布局
        layout(constraints.maxWidth, height) {
            // 第二次遍历：放置元素
            placeables.forEachIndexed { index, placeable ->
                val position = positions[index]
                placeable.place(position.x.roundToInt(), position.y.roundToInt())
            }
        }
    }
}

// 卡片数据
data class CardData(
    val title: String,
    val color: Color
)

// 拖动状态
enum class DragState {
    NONE, DRAGGING_LEFT, DRAGGING_RIGHT
}

// 滑动方向
enum class SwipeDirection {
    NONE, LEFT, RIGHT
}

@Composable
fun StackedCardsLayout(
    modifier: Modifier = Modifier,
    cardCount: Int,
    topCardIndex: Int,
    dragState: DragState,
    onDragStateChanged: (DragState) -> Unit,
    onSwipe: (SwipeDirection) -> Unit,
    content: @Composable (Int) -> Unit
) {
    // 状态
    var dragAmount by remember { mutableStateOf(0f) }
    val dragThreshold = 0.4f
    
    Box(modifier = modifier) {
        // 显示最多3张卡片
        val visibleCount = minOf(3, cardCount)
        
        for (i in visibleCount - 1 downTo 0) {
            key(topCardIndex + i) {
                Box(
                    modifier = Modifier
                        .fillMaxSize()
                        .stackedCardModifier(
                            position = i,
                            dragAmount = if (i == 0) dragAmount else 0f
                        )
                        .then(
                            if (i == 0) {
                                Modifier.pointerInput(Unit) {
                                    detectHorizontalDragGestures(
                                        onDragStart = {
                                            onDragStateChanged(DragState.NONE)
                                        },
                                        onDragEnd = {
                                            // 检查是否达到滑动阈值
                                            val direction = when {
                                                dragAmount < -dragThreshold -> SwipeDirection.LEFT
                                                dragAmount > dragThreshold -> SwipeDirection.RIGHT
                                                else -> SwipeDirection.NONE
                                            }
                                            
                                            if (direction != SwipeDirection.NONE) {
                                                onSwipe(direction)
                                            }
                                            
                                            // 重置状态
                                            dragAmount = 0f
                                            onDragStateChanged(DragState.NONE)
                                        },
                                        onDragCancel = {
                                            // 重置状态
                                            dragAmount = 0f
                                            onDragStateChanged(DragState.NONE)
                                        },
                                        onHorizontalDrag = { change, dragAmountDelta ->
                                            change.consume()
                                            
                                            // 更新拖动状态
                                            dragAmount = (dragAmount + dragAmountDelta / size.width)
                                                .coerceIn(-1f, 1f)
                                            
                                            // 更新拖动方向
                                            onDragStateChanged(
                                                when {
                                                    dragAmount < 0 -> DragState.DRAGGING_LEFT
                                                    dragAmount > 0 -> DragState.DRAGGING_RIGHT
                                                    else -> DragState.NONE
                                                }
                                            )
                                        }
                                    )
                                }
                            } else {
                                Modifier
                            }
                        )
                ) {
                    content(i)
                }
            }
        }
    }
}
