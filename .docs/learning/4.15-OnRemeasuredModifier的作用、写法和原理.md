# 4.15 OnRemeasuredModifier 的作用、写法和原理

> "今天我们要聊一个'偷窥'布局过程的修饰符：OnRemeasuredModifier！它就像是布局系统的'监听器'
>
，每当组件被重新测量时，它都能第一时间获取到最新的尺寸信息。掌握了它，你就能在组件尺寸变化的瞬间做出各种神奇的响应！"
📏🔍

## 概念介绍

OnRemeasuredModifier 是 Jetpack Compose
中一个强大但相对低调的修饰符，它允许开发者在组件完成测量后立即获取到组件的尺寸信息。与其他修饰符不同，OnRemeasuredModifier
不会改变组件的外观或行为，而是提供了一种观察组件测量结果的机制。

在 Compose 的布局过程中，每个组件都会经历测量（Measure）和放置（Place）两个阶段。OnRemeasuredModifier
在测量阶段完成后、放置阶段开始前被触发，这使得它成为获取组件最终尺寸的理想时机。

这个修饰符特别适用于以下场景：

1. 需要根据组件的实际尺寸调整其他 UI 元素
2. 实现复杂的动画效果，如尺寸变化的过渡动画
3. 记录和分析组件的尺寸变化
4. 在自定义布局中进行精确的位置计算

在最新版本的 Compose 中，OnRemeasuredModifier 通过 `onRemeasured` 修饰符函数来使用，它提供了一种简洁而强大的方式来响应组件的尺寸变化。

## 知识要点

- **OnRemeasuredModifier 的基本概念**：
    - 触发时机：组件测量完成后、放置前
    - 提供的信息：组件的尺寸（宽度和高度）
    - 与其他布局相关修饰符的区别

- **使用方式**：
    - `onRemeasured` 修饰符函数的参数和返回值
    - 回调函数的作用域和限制
    - 与状态管理的结合使用

- **执行时机**：
    - 在 Compose 布局流程中的位置
    - 与 `onGloballyPositioned` 和 `onSizeChanged` 的区别
    - 重组对 OnRemeasuredModifier 的影响

- **性能考虑**：
    - 回调函数的执行频率
    - 避免在回调中触发重组
    - 优化建议和最佳实践

- **实际应用场景**：
    - 测量文本尺寸
    - 实现自适应布局
    - 创建尺寸感知的动画
    - 在自定义布局中的应用

```kotlin
@Composable
fun BasicOnRemeasuredExample() {
    var boxSize by remember { mutableStateOf(IntSize.Zero) }
    
    Column(
        modifier = Modifier
            .fillMaxWidth()
            .padding(16.dp)
    ) {
        // 使用 onRemeasured 获取组件尺寸
```

```kotlin
@Composable
private fun StaggeredGrid(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier
    ) { measurables, constraints ->
        // 列宽
        val columnWidth = constraints.maxWidth / 2
        
        // 列高度
        val columnHeights = IntArray(2) { 0 }
        
        // 测量子元素
        val placeables = measurables.mapIndexed { index, measurable ->
            // 确定放置在哪一列
            val column = columnHeights.indexOf(columnHeights.minOrNull() ?: 0)
            
            // 测量子元素
            val placeable = measurable.measure(
                constraints.copy(
                    minWidth = columnWidth,
                    maxWidth = columnWidth
                )
            )
            
            // 更新列高度
            columnHeights[column] += placeable.height
            
            // 返回子元素和它的列
            column to placeable
        }
        
        // 计算总高度
        val height = columnHeights.maxOrNull()?.coerceIn(
            constraints.minHeight,
            constraints.maxHeight
        ) ?: constraints.minHeight
        
        // 放置子元素
        layout(constraints.maxWidth, height) {
            // 跟踪每列的当前Y坐标
            val columnY = IntArray(2) { 0 }
            
            placeables.forEach { (column, placeable) ->
                // 计算X坐标
                val x = column * columnWidth
                // 获取当前Y坐标
                val y = columnY[column]
                
                // 放置子元素
                placeable.place(x, y)
                
                // 更新Y坐标
                columnY[column] += placeable.height
            }
        }
    }
}

@Composable
private fun StaggeredGridItem(

    modifier: Modifier = Modifier
) {
    // 根据索引生成不同高度

            .height(height)

        colors = CardDefaults.cardColors(
            containerColor = listOf(
                Color(0xFFE57373),
                Color(0xFF81C784),
                Color(0xFF64B5F6),
                Color(0xFFFFB74D),
                Color(0xFF9575CD)
            )[index % 5]
        )
    ) {
        Box(
            modifier = Modifier.fillMaxSize(),

        ) {
```

## OnRemeasuredModifier 的原理

### 布局流程中的位置

在 Compose 的布局流程中，OnRemeasuredModifier 的触发时机非常特殊。以下是简化的布局流程：

1. **组合阶段**：创建 UI 树
2. **测量阶段**：确定每个组件的尺寸
3. **OnRemeasuredModifier 回调**：在测量完成后立即触发
4. **放置阶段**：根据测量结果确定每个组件的位置
5. **绘制阶段**：渲染 UI

这意味着 OnRemeasuredModifier 可以在组件被放置之前获取到其最终尺寸，这对于需要根据尺寸进行调整的场景非常有用。

### 实现原理

OnRemeasuredModifier 的实现原理可以简化为以下代码：

```kotlin
// 简化的 OnRemeasuredModifier 实现
class OnRemeasuredModifier(
    private val onRemeasured: (IntSize) -> Unit
) : LayoutModifier {
    override fun MeasureScope.measure(
        measurable: Measurable,
        constraints: Constraints
    ): MeasureResult {
        // 测量子元素
        val placeable = measurable.measure(constraints)
        
        // 获取尺寸
        val size = IntSize(placeable.width, placeable.height)
        
        // 调用回调
        onRemeasured(size)
        
        // 返回测量结果
        return layout(placeable.width, placeable.height) {
            placeable.place(0, 0)
        }
    }
}

// 扩展函数
fun Modifier.onRemeasured(onRemeasured: (IntSize) -> Unit): Modifier =
    this.then(OnRemeasuredModifier(onRemeasured))
```

从实现可以看出，OnRemeasuredModifier 是一个 LayoutModifier，它在测量子元素后、创建布局结果前调用回调函数，传递测量得到的尺寸信息。

### 与其他布局相关修饰符的比较

OnRemeasuredModifier 与其他布局相关的修饰符有一些重要的区别：

1. **与 onSizeChanged 的区别**：
    - `onSizeChanged` 在 Android View 系统中使用，而 `onRemeasured` 是 Compose 特有的
    - `onRemeasured` 在测量后立即触发，而 `onSizeChanged` 在布局完成后触发

2. **与 onGloballyPositioned 的区别**：
    - `onGloballyPositioned` 提供的是组件在全局坐标系中的位置和尺寸
    - `onGloballyPositioned` 在布局阶段完成后触发
    - `onGloballyPositioned` 提供更多信息（位置、尺寸、边界等）

3. **与 layout 修饰符的区别**：
    - `layout` 修饰符可以修改组件的测量和放置行为
    - `onRemeasured` 只是观察测量结果，不会修改布局


## 常见问题

### 1. 为什么我的 onRemeasured 回调被多次触发？

**问题**：我注意到 `onRemeasured` 回调在初始化时被多次触发，这是正常的吗？

**解答**：是的，这是正常的行为。`onRemeasured` 回调会在以下情况下触发：

1. **初始布局**：组件首次测量时
2. **重组**：当组件或其祖先重组时
3. **尺寸变化**：当组件的约束条件变化导致尺寸变化时

在 Compose 的初始化阶段，可能会进行多次测量以确定最终尺寸，这会导致回调被多次触发。如果你只关心尺寸的实际变化，可以在回调中添加条件检查：

```kotlin
var previousSize by remember { mutableStateOf(IntSize.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size ->
            if (size != previousSize) {
                // 尺寸确实发生了变化
                // 执行相应操作
                previousSize = size
            }
        }
)
```

### 2. onRemeasured 与 onGloballyPositioned 哪个更适合我的需求？

**问题**：我需要获取组件的尺寸信息，应该使用 `onRemeasured` 还是 `onGloballyPositioned`？

**解答**：选择取决于你的具体需求：

- **使用 onRemeasured 的情况**：
    - 你只需要组件的尺寸信息（宽度和高度）
    - 你需要在布局阶段尽早获取尺寸信息
    - 你不需要组件在全局坐标系中的位置信息

- **使用 onGloballyPositioned 的情况**：
    - 你需要组件在全局坐标系中的位置信息
    - 你需要更详细的布局信息（如边界、可见区域等）
    - 你需要在布局完全完成后获取信息

如果你只关心组件的尺寸，并且希望在布局过程中尽早获取这些信息，`onRemeasured`
是更好的选择。如果你需要更全面的布局信息，或者需要知道组件在屏幕上的确切位置，
`onGloballyPositioned` 更合适。

```kotlin
// onRemeasured 示例
Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size ->
            // 只获取尺寸信息
            val width = size.width
            val height = size.height
        }
)

// onGloballyPositioned 示例
Box(
    modifier = Modifier
        .fillMaxWidth()
        .onGloballyPositioned { coordinates ->
            // 获取尺寸信息
            val size = coordinates.size
            
            // 获取位置信息
            val position = coordinates.positionInRoot()
            
            // 获取边界信息
            val bounds = coordinates.boundsInWindow()
        }
)
```

### 3. 在 onRemeasured 回调中更新状态导致无限循环怎么办？

**问题**：当我在 `onRemeasured` 回调中更新状态时，似乎触发了无限循环的重组。如何避免这个问题？

**解答**：这是一个常见的陷阱。当你在 `onRemeasured` 回调中更新状态时，可能会触发重组，这又会导致新的测量，从而再次触发
`onRemeasured` 回调，形成无限循环。

避免这个问题的方法有几种：

1. **添加条件检查**：只在尺寸实际变化时更新状态

```kotlin
var previousSize by remember { mutableStateOf(IntSize.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size ->
            if (size != previousSize) {
                previousSize = size
                // 安全地更新其他状态
                someState = calculateNewState(size)
            }
        }
)
```

2. **使用 LaunchedEffect 延迟更新**：将状态更新移到协程中

```kotlin
var size by remember { mutableStateOf(IntSize.Zero) }
var derivedState by remember { mutableStateOf(0) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { newSize ->
            size = newSize
        }
)

// 在单独的效应中处理状态更新
LaunchedEffect(size) {
    // 只有当尺寸真正变化时才会执行
    derivedState = calculateNewState(size)
}
```

3. **使用 derivedStateOf**：对于可以从尺寸派生的状态

```kotlin
var size by remember { mutableStateOf(IntSize.Zero) }

// 派生状态
val derivedState by remember {
    derivedStateOf {
        calculateNewState(size)
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { newSize ->
            size = newSize
        }
)
```

### 4. 如何在自定义布局中使用 onRemeasured？

**问题**：我正在创建一个自定义布局，如何在其中使用 `onRemeasured` 来获取子元素的尺寸？

**解答**：在自定义布局中，你已经可以直接访问子元素的测量结果，不需要使用 `onRemeasured`
。但是，如果你想让自定义布局的用户能够获取布局本身的尺寸，你可以在自定义布局的实现中添加一个回调参数：

```kotlin
@Composable
fun CustomLayout(
    modifier: Modifier = Modifier,
    onSizeChanged: (IntSize) -> Unit = {}, // 添加回调参数
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier.onRemeasured(onSizeChanged) // 使用 onRemeasured 传递尺寸
    ) { measurables, constraints ->
        // 测量子元素
        val placeables = measurables.map { measurable ->
            measurable.measure(constraints)
        }
        
        // 计算布局尺寸
        val width = placeables.maxOfOrNull { it.width } ?: 0
        val height = placeables.sumOf { it.height }
        
        // 创建布局
        layout(width, height) {
            // 放置子元素
            var y = 0
            placeables.forEach { placeable ->
                placeable.place(0, y)
                y += placeable.height
            }
        }
    }
}
```

如果你需要获取每个子元素的尺寸，可以让用户在子元素上应用 `onRemeasured` 修饰符：

```kotlin
@Composable
fun CustomLayoutExample() {
    var childSizes by remember { mutableStateOf(listOf<IntSize>()) }
    
    CustomLayout(
        modifier = Modifier.fillMaxWidth()
    ) {
        // 子元素
        repeat(3) { index ->
            Box(
                modifier = Modifier
                    .fillMaxWidth()
                    .height(50.dp)
                    .onRemeasured { size ->
                        // 更新子元素尺寸列表
                        val newSizes = childSizes.toMutableList()
                        while (newSizes.size <= index) {
                            newSizes.add(IntSize.Zero)
                        }
                        newSizes[index] = size
                        childSizes = newSizes
                    }
            )
        }
    }
}
```

### 5. onRemeasured 会影响性能吗？

**问题**：频繁使用 `onRemeasured` 会对性能产生负面影响吗？

**解答**：`onRemeasured` 本身的性能开销相对较小，但不恰当的使用可能会导致性能问题。以下是一些性能考虑和最佳实践：

1. **避免在回调中执行耗时操作**：回调在主线程上执行，耗时操作会阻塞 UI。

2. **避免触发重组**：如前所述，在回调中更新状态可能导致无限循环的重组。

3. **减少回调频率**：如果你只关心显著的尺寸变化，可以添加阈值检查。

```kotlin
var previousSize by remember { mutableStateOf(IntSize.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size ->
            // 只有当尺寸变化超过阈值时才处理
            if (abs(size.width - previousSize.width) > 10 ||
                abs(size.height - previousSize.height) > 10) {
                previousSize = size
                // 处理尺寸变化
            }
        }
)
```

4. **使用 remember 缓存计算结果**：避免在每次回调中重复相同的计算。

```kotlin
var size by remember { mutableStateOf(IntSize.Zero) }

// 缓存计算结果
val aspectRatio by remember(size) {
    derivedStateOf {
        if (size.height != 0) size.width.toFloat() / size.height else 0f
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size = it }
)
```

5. **考虑使用 produceState 或 LaunchedEffect**：对于需要异步处理的情况。

```kotlin
var size by remember { mutableStateOf(IntSize.Zero) }

// 异步处理尺寸变化
LaunchedEffect(size) {
    if (size != IntSize.Zero) {
        // 在协程中执行可能耗时的操作
        val result = withContext(Dispatchers.Default) {
            performComplexCalculation(size)
        }
        // 更新状态
        calculationResult = result
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onRemeasured { size = it }
)
```

总的来说，`onRemeasured` 本身不会显著影响性能，但你需要谨慎处理回调中的操作，特别是涉及状态更新和复杂计算的情况。

```kotlin
            Column(modifier = Modifier.padding(16.dp)) {
                Text(
                    "卡片信息:",
                    fontWeight = FontWeight.Bold,
                    modifier = Modifier.padding(bottom = 8.dp)
                )
                
                Text("状态: ${if (expanded) "已展开" else "已收起"}")
                Text("尺寸: ${cardSize.width} × ${cardSize.height} px")
                Text("宽高比: ${
                    if (cardSize.height > 0) 
                        String.format("%.2f", cardSize.width.toFloat() / cardSize.height)
                    else 
                        "N/A"
                }")
                Text("动画进度: ${String.format("%.2f", animationProgress)}")
                
                LinearProgressIndicator(
                    progress = animationProgress,
                    modifier = Modifier
                        .fillMaxWidth()
                        .padding(top = 8.dp)
                )
                
                Text(
                    "提示: 点击卡片切换展开/收起状态",
                    style = MaterialTheme.typography.bodySmall,
                    color = Color.Gray,
                    modifier = Modifier.padding(top = 8.dp)
                )
            }
        }
    }
```
