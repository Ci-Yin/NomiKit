# 4.14 addBefore() 和 addAfter() 的区别以及最新版代码的调整

## 概念介绍

在Jetpack Compose中，修饰符（Modifier）是通过链式调用组合在一起的，默认情况下，我们使用`then()`
方法将多个修饰符连接起来。但有时，我们需要更精确地控制修饰符的应用顺序，这就是`addBefore()`和
`addAfter()`这两个方法的用武之地。

这两个方法允许我们在已有的修饰符链中的特定位置插入新的修饰符，从而精确控制修饰符的执行顺序。理解它们的区别和使用场景，对于创建复杂而高效的UI组件至关重要。

在Compose的早期版本中，`addBefore()`和`addAfter()`
是作为Modifier接口的扩展函数提供的。然而，在最新版本的Compose中，这两个方法已经被重新设计和调整，以提供更一致和可预测的行为。

## 知识要点

- **修饰符链的基本概念**：

- **addBefore() 和 addAfter() 的区别**：
    - `addBefore()`：在指定修饰符之前插入新修饰符
    - `addAfter()`：在指定修饰符之后插入新修饰符
    - 它们对修饰符执行顺序的影响

- **最新版本的调整**：

- **性能考虑**：

    - 与直接使用`then()`的性能比较
    - 优化建议

## 原理解析

### 修饰符链的内部结构

要理解`addBefore()`和`addAfter()`的工作原理，我们需要先了解修饰符链的内部结构：

```kotlin
// 简化的Modifier接口
interface Modifier {
    // 空的Modifier实例
    companion object : Modifier {
        // 实现细节...
    }
    
    // 组合两个修饰符
    fun then(other: Modifier): Modifier = 
        if (other === Modifier) this else CombinedModifier(this, other)
}

// 组合修饰符的实现
private class CombinedModifier(
    private val outer: Modifier,
    private val inner: Modifier
) : Modifier {
    // 实现细节...
}
```

修饰符链是通过`CombinedModifier`类实现的，它将两个修饰符组合在一起，形成一个链式结构。当我们调用
`a.then(b).then(c)`
时，实际上创建了这样的结构：`CombinedModifier(CombinedModifier(a, b), c)`。

### addBefore() 和 addAfter() 的实现原理

在早期版本中，`addBefore()`和`addAfter()`的实现大致如下：

```kotlin
// 早期版本的addBefore实现（简化版）
fun Modifier.addBefore(after: Modifier, add: Modifier): Modifier {
    // 如果after是空修饰符，直接返回this.then(add)
    if (after === Modifier) return this.then(add)
    // 如果add是空修饰符，直接返回this
    if (add === Modifier) return this
    
    // 遍历修饰符链，找到after的位置
    return foldOut(Modifier) { element, acc ->
        if (element === after) {
            // 找到after，在它之前插入add
            add.then(element).then(acc)
        } else {
            // 继续构建链
            element.then(acc)
        }
    }
}

// 早期版本的addAfter实现（简化版）
fun Modifier.addAfter(background: Modifier, add: Modifier): Modifier {
    // 如果background是空修饰符，直接返回add.then(this)
    if (background === Modifier) return add.then(this)
    // 如果add是空修饰符，直接返回this
    if (add === Modifier) return this
    
    // 遍历修饰符链，找到background的位置
    return foldOut(Modifier) { element, acc ->
        if (element === background) {
            // 找到background，在它之后插入add
            element.then(add).then(acc)
        } else {
            // 继续构建链
            element.then(acc)
        }
    }
}
```

这些方法通过遍历修饰符链，找到指定修饰符的位置，然后在该位置之前或之后插入新的修饰符。

### 最新版本的调整原因

在最新版本中，这些方法被移除或重新设计的原因包括：

1. **性能考虑**：遍历修饰符链可能导致性能问题，特别是对于长链。
2. **可预测性**：这些方法的行为可能不够直观，导致开发者混淆。
3. **API简化**：Compose团队希望提供更简单、更一致的API。
4. **替代方案**：`Modifier.composed()`提供了更灵活的方式来创建复杂的修饰符组合。

### 新版本中的替代方案

在最新版本中，我们可以使用以下方法来替代`addBefore()`和`addAfter()`：

1. **直接使用链式调用**：在大多数情况下，直接使用`then()`方法的链式调用就足够了。
2. **使用`Modifier.composed()`**：对于需要根据条件应用不同修饰符的情况，使用`composed()`方法。
3. **创建自定义修饰符**：对于复杂的修饰符组合，创建自定义的修饰符扩展函数。

```kotlin
// 使用composed()替代addBefore和addAfter
fun Modifier.customLayout(
    padding: Dp,
    cornerRadius: Dp
): Modifier = composed {
    this
        .clip(RoundedCornerShape(cornerRadius)) // 相当于addBefore(padding, clip)
        .padding(padding)
        .border(2.dp, Color.Black) // 相当于addAfter(padding, border)
}
```

### 3. 使用composed()会有性能影响吗？

**问题**：频繁使用`Modifier.composed()`会对性能产生负面影响吗？

**解答**：`Modifier.composed()`确实会引入一些额外的开销，但在大多数情况下，这种开销是可以接受的。以下是一些注意事项：

1. **重组成本**：`composed()`创建了一个新的可组合函数，这意味着它参与重组过程，可能导致额外的重组成本。

2. **内存分配**：每次调用`composed()`都会创建新的对象，这可能导致额外的内存分配。

3. **使用建议**：
    - 对于简单的修饰符组合，直接使用链式调用。
    - 对于需要访问可组合环境（如LocalDensity）的修饰符，使用`composed()`。
    - 对于条件性应用的修饰符，使用`composed()`是合适的。
    - 避免在热路径（频繁重组的部分）中过度使用`composed()`。

```kotlin
// 优化composed()使用的示例
// 不推荐：在循环中频繁创建composed修饰符
@Composable
fun IneffectiveExample(items: List<Item>) {
    LazyColumn {
        items(items) { item ->
            // 每个项目都创建新的composed修饰符
            Box(
                modifier = Modifier
                    .fillMaxWidth()
                    .composed {
                        if (item.isSelected) {
                            this.background(Color.Blue)
                        } else {
                            this.background(Color.White)
                        }
                    }
            ) {
                Text(item.name)
            }
        }
    }
}

// 推荐：提取到可重用的函数
fun Modifier.itemBackground(isSelected: Boolean): Modifier = composed {

    }
}

@Composable
fun EffectiveExample(items: List<Item>) {

            Box(
                modifier = Modifier

            }
        }

}
```

```kotlin
// 修饰符构建器
class ModifierBuilder {
    private var backgroundModifier: Modifier = Modifier
    private var borderModifier: Modifier = Modifier
    private var paddingModifier: Modifier = Modifier
    private var shapeModifier: Modifier = Modifier
    private var interactionModifier: Modifier = Modifier
    
    // 设置背景
    fun background(color: Color): ModifierBuilder {
        backgroundModifier = Modifier.background(color)
        return this
    }
    
    // 设置背景带形状
    fun background(color: Color, shape: Shape): ModifierBuilder {
        backgroundModifier = Modifier.background(color, shape)
        return this
    }
    
    // 设置边框
    fun border(width: Dp, color: Color, shape: Shape = RectangleShape): ModifierBuilder {
        borderModifier = Modifier.border(width, color, shape)
        return this
    }
    
    // 设置内边距
    fun padding(all: Dp): ModifierBuilder {
        paddingModifier = Modifier.padding(all)
        return this
    }
    
    // 设置不同方向的内边距
    fun padding(
        horizontal: Dp = 0.dp,
        vertical: Dp = 0.dp
    ): ModifierBuilder {
        paddingModifier = Modifier.padding(horizontal = horizontal, vertical = vertical)
        return this
    }
    
    // 设置形状裁剪
    fun clip(shape: Shape): ModifierBuilder {
        shapeModifier = Modifier.clip(shape)
        return this
    }
    
    // 设置点击事件
    fun clickable(onClick: () -> Unit): ModifierBuilder {
        interactionModifier = Modifier.clickable(onClick = onClick)
        return this
    }
    
    // 构建最终的修饰符
    fun build(): Modifier = Modifier
        .then(shapeModifier)
        .then(backgroundModifier)
        .then(borderModifier)
        .then(interactionModifier)
        .then(paddingModifier)
}
```
