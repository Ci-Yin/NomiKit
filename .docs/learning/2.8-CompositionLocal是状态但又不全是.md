# 2.8 CompositonLocal——是状态但又不全是

> "
>
CompositionLocal就像空气，无处不在却又看不见摸不着。它让数据像魔法一样从组件树的顶层悄悄传递到任何需要的地方，是Compose中最神秘的状态传递方式！"
> 🪄

## 概念介绍

CompositionLocal是Jetpack
Compose中一种特殊的数据传递机制，它允许在组合树中隐式传递数据，而不需要通过每个中间组件的参数显式传递。这种机制特别适合于主题、资源、配置等全局或半全局数据的传递。

CompositionLocal既有状态的特性——它可以被观察和触发重组，又不完全是状态——它主要用于数据传递而非状态管理。理解CompositionLocal的工作原理和适用场景，对于构建可维护的Compose应用至关重要。

本节将深入探讨CompositionLocal的概念、使用方法、最佳实践以及与其他状态管理方式的区别。

## 知识要点

- **CompositionLocal的基本概念**：隐式数据传递机制
- **创建和提供值**：compositionLocalOf和CompositionLocalProvider
- **读取值**：current属性和LocalContext等内置CompositionLocal
- **作用域**：CompositionLocal的值作用范围
- **静态与动态值**：staticCompositionLocalOf vs compositionLocalOf
- **与状态的关系**：CompositionLocal如何触发重组
- **常见使用场景**：主题、资源、依赖注入等
- **避免滥用**：何时不应该使用CompositionLocal

## 基础代码示例

### 创建和使用CompositionLocal

```kotlin
// 创建一个CompositionLocal
val LocalUserName = compositionLocalOf { "Guest" }

@Composable
fun CompositionLocalBasicExample() {
    // 读取当前值
    val userName = LocalUserName.current
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "当前用户: $userName",
            style = MaterialTheme.typography.headlineMedium
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 提供新值
        CompositionLocalProvider(LocalUserName provides "Admin") {
            // 在这个作用域内，LocalUserName.current 的值是 "Admin"
            NestedComponent()
        }
    }
}

@Composable
fun NestedComponent() {
    // 自动获取上层提供的值
    val userName = LocalUserName.current
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "嵌套组件中的用户: $userName",
            style = MaterialTheme.typography.titleLarge
        )
    }
}
```

### 使用CompositionLocal进行依赖注入

```kotlin
// 1. 定义服务接口
interface UserRepository {
    fun getCurrentUser(): User
    fun updateUser(user: User)
}

data class User(val id: String, val name: String, val email: String)

// 2. 实现服务
class FakeUserRepository : UserRepository {
    private var currentUser = User("1", "John Doe", "john@example.com")
    
    override fun getCurrentUser(): User = currentUser
    
    override fun updateUser(user: User) {
        currentUser = user
    }
}

// 3. 创建CompositionLocal
val LocalUserRepository = compositionLocalOf<UserRepository> { 
    error("UserRepository not provided") 
}

// 4. 创建应用级提供者
@Composable
fun AppDependencies(content: @Composable () -> Unit) {
    // 在实际应用中，这些依赖可能来自Dagger/Hilt等DI框架
    val userRepository = remember { FakeUserRepository() }
    
    CompositionLocalProvider(
        LocalUserRepository provides userRepository
    ) {
        content()
    }
}

// 5. 在组件中使用依赖
@Composable
fun UserProfileScreen() {
    // 获取依赖
    val userRepository = LocalUserRepository.current
    
    // 获取用户数据
    val user = remember { userRepository.getCurrentUser() }
    
    // 创建编辑状态
    var editedName by remember { mutableStateOf(user.name) }
    var isEditing by remember { mutableStateOf(false) }
    
    Column(modifier = Modifier.padding(16.dp)) {
        if (isEditing) {
            // 编辑模式
            OutlinedTextField(
                value = editedName,
                onValueChange = { editedName = it },
                label = { Text("用户名") },
                modifier = Modifier.fillMaxWidth()
            )
            
            Spacer(modifier = Modifier.height(16.dp))
            
            Row(
                modifier = Modifier.fillMaxWidth(),
                horizontalArrangement = Arrangement.End
            ) {
                TextButton(onClick = { isEditing = false }) {
                    Text("取消")
                }
                
                Button(
                    onClick = {
                        // 保存更改
                        userRepository.updateUser(user.copy(name = editedName))
                        isEditing = false
                    },
                    modifier = Modifier.padding(start = 8.dp)
                ) {
                    Text("保存")
                }
            }
        } else {
            // 显示模式
            Text(
                text = "用户资料",

            Spacer(modifier = Modifier.height(16.dp))
            
            Text("ID: ${user.id}")

            Text("邮箱: ${user.email}")
            
            Spacer(modifier = Modifier.height(16.dp))
            
            Button(
                onClick = { isEditing = true },
                modifier = Modifier.align(Alignment.End)

                Text("编辑")
            }
        }
    }
}
```

## 常见问题

### 1. CompositionLocal与普通参数传递有什么区别？

**答**：CompositionLocal和普通参数传递的主要区别在于：

- **传递方式**：
    - 普通参数传递是显式的，每个中间组件都需要接收并传递参数
    - CompositionLocal是隐式的，中间组件不需要知道这些数据的存在

- **适用场景**：
    - 普通参数适合传递组件直接需要的数据
    - CompositionLocal适合传递全局或半全局的数据，如主题、资源、依赖等

- **可维护性**：
    - 普通参数使数据流更加明确，但可能导致参数列表膨胀
    - CompositionLocal减少了参数传递的负担，但可能使数据流不那么明显

一般来说，应该优先使用普通参数传递，只有当参数需要穿过多层组件且大多数中间组件不需要这些参数时，才考虑使用CompositionLocal。

### 2. compositionLocalOf和staticCompositionLocalOf有什么区别？

**答**：这两个函数都用于创建CompositionLocal，但它们在重组行为上有重要区别：

- **compositionLocalOf**：
    - 当提供的值变化时，只有直接读取该值的组件会重组
    - 适用于可能频繁变化的值
    - 有轻微的运行时开销，因为需要跟踪哪些组件读取了该值

- **staticCompositionLocalOf**：
    - 当提供的值变化时，整个提供该值的作用域都会重组
    - 适用于几乎不会变化的值（如资源、服务等）
    - 性能开销更小，因为不需要跟踪读取

选择取决于值的变化频率和重组范围的需求。一般来说，对于主题、本地化等可能变化的值，使用
`compositionLocalOf`；对于几乎不变的值，如服务依赖，使用
`staticCompositionLocalOf`。

### 3. 什么情况下应该避免使用CompositionLocal？

**答**：应该避免在以下情况使用CompositionLocal：

1. **传递组件特定数据**：如果数据只被少数几个相关组件使用，应该使用普通参数传递。

2. **频繁变化的状态**：如果数据频繁变化且变化需要精确控制重组范围，使用状态提升可能更合适。

3. **业务逻辑数据**：CompositionLocal不应该用于传递业务逻辑数据，这会使数据流难以追踪和测试。

4. **可测试性要求高的场景**：CompositionLocal使组件对外部环境产生隐式依赖，可能使测试变得复杂。

5. **简单的组件层次**：如果组件层次不深，普通参数传递更直接、更明确。

过度使用CompositionLocal会导致"魔法"代码，使数据流难以理解和维护。应该将其视为一种特殊工具，而非默认选择。

### 4. CompositionLocal值的变化会触发重组吗？

**答**：是的，CompositionLocal值的变化会触发重组，但触发方式取决于创建方法：

- 使用`compositionLocalOf`创建的CompositionLocal，当值变化时，只有直接读取该值的组件会重组。

- 使用`staticCompositionLocalOf`创建的CompositionLocal，当值变化时，整个提供该值的作用域都会重组。

重要的是，CompositionLocal的值变化是在`CompositionLocalProvider`处发生的，而不是值本身的内部变化。例如：

```kotlin
// 这会触发重组
CompositionLocalProvider(LocalColor provides Color.Red) {
    // ...
}

// 稍后变为
CompositionLocalProvider(LocalColor provides Color.Blue) {
    // ...
}
```

但如果CompositionLocal的值是一个可变对象，修改该对象的内部状态不会自动触发重组：

```kotlin
// 定义一个可变对象
class MutableSettings {
    var fontSize = 14
}

// 提供该对象
val settings = remember { MutableSettings() }
CompositionLocalProvider(LocalSettings provides settings) {
    // ...
}

// 修改对象内部状态不会自动触发重组
settings.fontSize = 16  // 不会触发使用LocalSettings的组件重组
```

在这种情况下，需要使用可观察状态（如MutableState）或手动触发重组。
