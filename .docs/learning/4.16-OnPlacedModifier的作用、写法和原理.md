# 4.16 OnPlacedModifier 的作用、写法和原理

> "今天我们要聊一个'窥探'布局放置过程的修饰符：OnPlacedModifier！它就像是布局系统的'侦探'
>
，每当组件被放置到屏幕上时，它都能立即获取到组件的位置信息。掌握了它，你就能在组件出现在屏幕上的瞬间做出各种精彩的响应！"
> 📍🔎

## 概念介绍

OnPlacedModifier 是 Jetpack Compose 中一个强大的修饰符，它允许开发者在组件完成放置（Placement）阶段后立即获取到组件的位置信息。与
OnRemeasuredModifier 关注组件的尺寸不同，OnPlacedModifier 更关注组件在布局中的确切位置。

在 Compose 的布局流程中，每个组件都会经历测量（Measure）和放置（Place）两个主要阶段。OnPlacedModifier
在放置阶段完成后被触发，这使得它成为获取组件最终位置的理想时机。

这个修饰符特别适用于以下场景：

1. 需要获取组件在父容器中的确切位置
2. 实现基于位置的动画效果，如入场动画
3. 创建依赖于组件位置的交互效果
4. 在自定义布局中进行精确的位置计算和调整
5. 实现高级的滚动效果和可见性检测

在最新版本的 Compose 中，OnPlacedModifier 通过 `onPlaced` 修饰符函数来使用，它提供了一种简洁而强大的方式来响应组件的位置变化。

## 知识要点

- **OnPlacedModifier 的基本概念**：
    - 触发时机：组件放置完成后

- **执行时机**：
    - 在 Compose 布局流程中的位置

    - 重组对 OnPlacedModifier 的影响

- **位置信息的处理**：
    - 理解坐标系统
    - 相对位置与绝对位置的转换

@Composable
private fun VisibilityAwareItem(
    index: Int,
    onVisibilityChanged: (Boolean) -> Unit
) {
    var itemPosition by remember { mutableStateOf(IntOffset.Zero) }
    var parentBounds by remember { mutableStateOf(Rect.Zero) }
    
    // 计算可见性
    val isVisible = remember(itemPosition, parentBounds) {
        if (parentBounds == Rect.Zero) false
        else {
            val itemRect = Rect(
                itemPosition.x.toFloat(),
                itemPosition.y.toFloat(),
                itemPosition.x.toFloat() + 100f, // 假设宽度为100
                itemPosition.y.toFloat() + 100f  // 假设高度为100
            )
            parentBounds.overlaps(itemRect)
        }
    }
    
    // 通知可见性变化
    LaunchedEffect(isVisible) {
        onVisibilityChanged(isVisible)
    }
    
    Box(
        modifier = Modifier
            .fillMaxWidth()
            .height(100.dp)
            .padding(vertical = 8.dp)
            .background(
                if (isVisible) Color(0xFF4CAF50).copy(alpha = 0.2f) else Color(0xFFE0E0E0),
                RoundedCornerShape(8.dp)
            )
            .onPlaced { coordinates ->
                // 获取项目位置
                itemPosition = coordinates.positionInParent().round()
                
                // 获取父容器边界
                val parent = coordinates.parentCoordinates
                if (parent != null) {
                    val parentSize = parent.size
                    parentBounds = Rect(
                        0f,
                        0f,
                        parentSize.width.toFloat(),
                        parentSize.height.toFloat()
                    )
                }
            },
        contentAlignment = Alignment.Center
    ) {
        Row(
            verticalAlignment = Alignment.CenterVertically,
            horizontalArrangement = Arrangement.spacedBy(8.dp)
        ) {
            Box(
                modifier = Modifier
                    .size(40.dp)
                    .background(
                        if (isVisible) Color(0xFF4CAF50) else Color(0xFFE0E0E0),
                        CircleShape
                    ),
                contentAlignment = Alignment.Center
            ) {
                Text(
                    text = "${index + 1}",
                    color = if (isVisible) Color.White else Color.Black
                )
            }
            
            Text(
                text = "项目 ${index + 1}",
                style = MaterialTheme.typography.bodyLarge,
                fontWeight = if (isVisible) FontWeight.Bold else FontWeight.Normal
            )

            } else {

## OnPlacedModifier 的原理

### 布局流程中的位置

在 Compose 的布局流程中，OnPlacedModifier 的触发时机非常特殊。以下是简化的布局流程：

1. **组合阶段**：创建 UI 树
2. **测量阶段**：确定每个组件的尺寸
3. **放置阶段**：根据测量结果确定每个组件的位置
4. **OnPlacedModifier 回调**：在放置完成后立即触发
5. **绘制阶段**：渲染 UI

这意味着 OnPlacedModifier 可以在组件被绘制之前获取到其最终位置，这对于需要根据位置进行调整的场景非常有用。

### 实现原理

OnPlacedModifier 的实现原理可以简化为以下代码：

```kotlin
// 简化的 OnPlacedModifier 实现
class OnPlacedModifier(
    private val onPlaced: (LayoutCoordinates) -> Unit
) : LayoutModifier {
    override fun MeasureScope.measure(
        measurable: Measurable,
        constraints: Constraints
    ): MeasureResult {
        // 测量子元素
        val placeable = measurable.measure(constraints)
        
        // 返回测量结果
        return layout(placeable.width, placeable.height) {
            // 放置子元素
            placeable.place(0, 0)
            
            // 获取布局坐标并调用回调
            onPlaced(coordinates)
        }
    }
}

// 扩展函数
fun Modifier.onPlaced(onPlaced: (LayoutCoordinates) -> Unit): Modifier =
    this.then(OnPlacedModifier(onPlaced))
```

从实现可以看出，OnPlacedModifier 是一个 LayoutModifier，它在放置子元素后调用回调函数，传递布局坐标信息。

### 与其他布局相关修饰符的比较

OnPlacedModifier 与其他布局相关的修饰符有一些重要的区别：

1. **与 onRemeasured 的区别**：
    - `onRemeasured` 在测量阶段完成后触发，关注组件的尺寸
    - `onPlaced` 在放置阶段完成后触发，关注组件的位置
    - `onRemeasured` 先于 `onPlaced` 触发

2. **与 onGloballyPositioned 的区别**：
    - `onPlaced` 提供的是组件在父容器中的相对位置
    - `onGloballyPositioned` 提供的是组件在全局坐标系中的位置
    - `onGloballyPositioned` 提供更多信息，但触发时机略晚

3. **与 layout 修饰符的区别**：
    - `layout` 修饰符可以修改组件的测量和放置行为
    - `onPlaced` 只是观察放置结果，不会修改布局

## 常见问题

### 1. 为什么我的 onPlaced 回调被多次触发？

**问题**：我注意到 `onPlaced` 回调在初始化时被多次触发，这是正常的吗？

**解答**：是的，这是正常的行为。`onPlaced` 回调会在以下情况下触发：

1. **初始布局**：组件首次放置时
2. **重组**：当组件或其祖先重组时
3. **位置变化**：当组件的位置发生变化时

在 Compose 的初始化阶段，可能会进行多次布局以确定最终位置，这会导致回调被多次触发。如果你只关心位置的实际变化，可以在回调中添加条件检查：

```kotlin
var previousPosition by remember { mutableStateOf(IntOffset.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            val position = coordinates.positionInParent().round()
            if (position != previousPosition) {
                // 位置确实发生了变化
                // 执行相应操作
                previousPosition = position
            }
        }
)
```

### 2. onPlaced 与 onGloballyPositioned 哪个更适合我的需求？

**问题**：我需要获取组件的位置信息，应该使用 `onPlaced` 还是 `onGloballyPositioned`？

**解答**：选择取决于你的具体需求：

- **使用 onPlaced 的情况**：
    - 你需要在布局阶段尽早获取位置信息
    - 你只需要组件在父容器中的相对位置
    - 你需要在绘制前进行位置相关的调整

- **使用 onGloballyPositioned 的情况**：
    - 你需要组件在全局坐标系中的位置
    - 你需要更详细的布局信息（如边界、可见区域等）
    - 你需要在布局完全完成后获取信息

如果你只关心组件在父容器中的位置，并且希望在布局过程中尽早获取这些信息，`onPlaced`
是更好的选择。如果你需要更全面的布局信息，或者需要知道组件在屏幕上的确切位置，
`onGloballyPositioned` 更合适。

```kotlin
// onPlaced 示例
Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            // 获取相对于父容器的位置
            val position = coordinates.positionInParent()
        }
)

// onGloballyPositioned 示例
Box(
    modifier = Modifier
        .fillMaxWidth()
        .onGloballyPositioned { coordinates ->
            // 获取相对于窗口的位置
            val windowPosition = coordinates.positionInWindow()
            
            // 获取相对于根组件的位置
            val rootPosition = coordinates.positionInRoot()
            
            // 获取边界信息
            val bounds = coordinates.boundsInWindow()
        }
)
```

### 3. 在 onPlaced 回调中更新状态导致无限循环怎么办？

**问题**：当我在 `onPlaced` 回调中更新状态时，似乎触发了无限循环的重组。如何避免这个问题？

**解答**：这是一个常见的陷阱。当你在 `onPlaced` 回调中更新状态时，可能会触发重组，这又会导致新的布局，从而再次触发
`onPlaced`
回调，形成无限循环。

避免这个问题的方法有几种：

1. **添加条件检查**：只在位置实际变化时更新状态

```kotlin
var previousPosition by remember { mutableStateOf(IntOffset.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            val position = coordinates.positionInParent().round()
            if (position != previousPosition) {
                previousPosition = position
                // 安全地更新其他状态
                someState = calculateNewState(position)
            }
        }
)
```

2. **使用 LaunchedEffect 延迟更新**：将状态更新移到协程中

```kotlin
var position by remember { mutableStateOf(IntOffset.Zero) }
var derivedState by remember { mutableStateOf(0) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            position = coordinates.positionInParent().round()
        }
)

// 在单独的效应中处理状态更新
LaunchedEffect(position) {
    // 只有当位置真正变化时才会执行
    derivedState = calculateNewState(position)
}
```

3. **使用 derivedStateOf**：对于可以从位置派生的状态

```kotlin
var position by remember { mutableStateOf(IntOffset.Zero) }

// 派生状态
val derivedState by remember {
    derivedStateOf {
        calculateNewState(position)
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            position = coordinates.positionInParent().round()
        }
)
```

### 4. 如何在自定义布局中使用 onPlaced？

**问题**：我正在创建一个自定义布局，如何在其中使用 `onPlaced` 来获取子元素的位置？

**解答**：在自定义布局中，你可以直接访问子元素的位置信息，不需要使用 `onPlaced`
。但是，如果你想让自定义布局的用户能够获取布局本身或子元素的位置，你可以在自定义布局的实现中添加回调参数：

```kotlin
@Composable
fun CustomLayout(
    modifier: Modifier = Modifier,
    onPositionChanged: (List<IntOffset>) -> Unit = {}, // 添加回调参数
    content: @Composable () -> Unit
) {
    Layout(
        content = content,
        modifier = modifier.onPlaced { coordinates ->
            // 可以在这里获取整个布局的位置
            val layoutPosition = coordinates.positionInParent().round()
            // ...
        }
    ) { measurables, constraints ->
        // 测量子元素
        val placeables = measurables.map { measurable ->
            measurable.measure(constraints)
        }
        
        // 计算布局尺寸
        val width = placeables.maxOfOrNull { it.width } ?: 0
        val height = placeables.sumOf { it.height }
        
        // 创建布局
        layout(width, height) {
            // 放置子元素并收集位置
            var y = 0
            val positions = mutableListOf<IntOffset>()
            
            placeables.forEach { placeable ->
                placeable.place(0, y)
                positions.add(IntOffset(0, y))
                y += placeable.height
            }
            
            // 通知位置变化
            onPositionChanged(positions)
        }
    }
}
```

如果你需要让用户在子元素上应用 `onPlaced` 修饰符，他们可以直接这样做：

```kotlin

        }
    ) {
        // 子元素

            Box(
                modifier = Modifier
                    .fillMaxWidth()
                    .height(50.dp)
                    .onPlaced { coordinates ->
                        // 获取子元素在其父容器中的位置
                        val position = coordinates.positionInParent().round()
                        // ...
                    }
            )
        }
    }
}
```

### 5. onPlaced 会影响性能吗？

**问题**：频繁使用 `onPlaced` 会对性能产生负面影响吗？

**解答**：`onPlaced` 本身的性能开销相对较小，但不恰当的使用可能会导致性能问题。以下是一些性能考虑和最佳实践：

1. **避免在回调中执行耗时操作**：回调在主线程上执行，耗时操作会阻塞 UI。

2. **避免触发重组**：如前所述，在回调中更新状态可能导致无限循环的重组。

3. **减少回调频率**：如果你只关心显著的位置变化，可以添加阈值检查。

```kotlin
var previousPosition by remember { mutableStateOf(IntOffset.Zero) }

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            val position = coordinates.positionInParent().round()
            // 只有当位置变化超过阈值时才处理
            if (abs(position.x - previousPosition.x) > 10 ||
                abs(position.y - previousPosition.y) > 10) {
                previousPosition = position
                // 处理位置变化
            }
        }
)
```

4. **使用 remember 缓存计算结果**：避免在每次回调中重复相同的计算。

```kotlin
var position by remember { mutableStateOf(IntOffset.Zero) }

// 缓存计算结果
val isInTopHalf by remember(position) {
    derivedStateOf {
        position.y < containerHeight / 2
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            position = coordinates.positionInParent().round()
        }
)
```

5. **考虑使用 produceState 或 LaunchedEffect**：对于需要异步处理的情况。

```kotlin
var position by remember { mutableStateOf(IntOffset.Zero) }

// 异步处理位置变化
LaunchedEffect(position) {
    if (position != IntOffset.Zero) {
        // 在协程中执行可能耗时的操作
        val result = withContext(Dispatchers.Default) {
            performComplexCalculation(position)
        }
        // 更新状态
        calculationResult = result
    }
}

Box(
    modifier = Modifier
        .fillMaxWidth()
        .onPlaced { coordinates ->
            position = coordinates.positionInParent().round()
        }
)
```

总的来说，`onPlaced` 本身不会显著影响性能，但你需要谨慎处理回调中的操作，特别是涉及状态更新和复杂计算的情况。

@Composable
fun MagneticSnapEffectExercise() {
    var dragPosition by remember { mutableStateOf(Offset.Zero) }
    var isDragging by remember { mutableStateOf(false) }

    // 计算最近的吸附点
    val nearestSnapPoint = remember(dragPosition, snapPoints) {
        if (snapPoints.isEmpty()) null
        else snapPoints.minByOrNull { (it - dragPosition).getDistance() }
    }
    
    // 计算是否应该吸附
    val shouldSnap = remember(dragPosition, nearestSnapPoint, isDragging) {
        if (nearestSnapPoint == null || isDragging) false
        else (nearestSnapPoint - dragPosition).getDistance() < 50f
    }
    
    // 计算最终位置
    val finalPosition = if (shouldSnap && nearestSnapPoint != null) nearestSnapPoint else dragPosition
    
    // 动画位置
    val animatedPosition by animateOffsetAsState(
        targetValue = finalPosition,
        animationSpec = spring(
            dampingRatio = Spring.DampingRatioMediumBouncy,
            stiffness = Spring.StiffnessLow
        ),
        label = "position"
    )

        modifier = Modifier
            .fillMaxWidth()
            .padding(16.dp)

                .height(400.dp)

                    // 创建吸附点
                    val size = coordinates.size
                    val width = size.width.toFloat()

                    // 生成网格吸附点

private fun Offset.getDistance(): Float {
    return sqrt(x * x + y * y)
}

@Composable
private fun SmartTooltip(

// 计算工具提示的最佳位置
private fun calculateTooltipPosition(
    anchorPosition: IntOffset,
    anchorSize: IntSize,
    tooltipSize: IntSize,
    containerSize: IntSize
): IntOffset {
    // 如果工具提示尺寸未知，返回默认位置
    if (tooltipSize == IntSize.Zero) {
        return IntOffset(
            anchorPosition.x,
            anchorPosition.y + anchorSize.height + 8
        )
    }
    
    // 尝试不同的放置位置，按优先级排序
    val positions = listOf(
        // 下方
        IntOffset(
            x = anchorPosition.x + (anchorSize.width - tooltipSize.width) / 2,
            y = anchorPosition.y + anchorSize.height + 8
        ),
        // 上方
        IntOffset(
            x = anchorPosition.x + (anchorSize.width - tooltipSize.width) / 2,
            y = anchorPosition.y - tooltipSize.height - 8
        ),
        // 右侧
        IntOffset(
            x = anchorPosition.x + anchorSize.width + 8,
            y = anchorPosition.y + (anchorSize.height - tooltipSize.height) / 2
        ),
        // 左侧
        IntOffset(
            x = anchorPosition.x - tooltipSize.width - 8,
            y = anchorPosition.y + (anchorSize.height - tooltipSize.height) / 2
        )
    )
    
    // 检查每个位置是否在容器内
    for (position in positions) {
        val tooltipRect = Rect(
            position.x.toFloat(),
            position.y.toFloat(),
            (position.x + tooltipSize.width).toFloat(),
            (position.y + tooltipSize.height).toFloat()
        )
        
        val containerRect = Rect(
            0f,
            0f,
            containerSize.width.toFloat(),
            containerSize.height.toFloat()
        )
        
        if (containerRect.contains(tooltipRect)) {
            return position
        }
    }
    
    // 如果所有位置都不完全在容器内，选择最佳位置并调整
    val bestPosition = positions.first()
    
    // 调整X坐标，确保不超出容器
    val adjustedX = bestPosition.x.coerceIn(
        0,
        (containerSize.width - tooltipSize.width).coerceAtLeast(0)
    )
    
    // 调整Y坐标，确保不超出容器
    val adjustedY = bestPosition.y.coerceIn(
        0,
        (containerSize.height - tooltipSize.height).coerceAtLeast(0)
    )
    
    return IntOffset(adjustedX, adjustedY)
}

// 获取放置位置的描述
private fun getPlacementDescription(
    anchorPosition: IntOffset,
    anchorSize: IntSize,
    tooltipPosition: IntOffset
): String {
    val anchorCenter = IntOffset(
        anchorPosition.x + anchorSize.width / 2,
        anchorPosition.y + anchorSize.height / 2
    )
    
    return when {
        tooltipPosition.y >= anchorPosition.y + anchorSize.height -> "下方"
        tooltipPosition.y + 1 <= anchorPosition.y -> "上方"
        tooltipPosition.x >= anchorPosition.x + anchorSize.width -> "右侧"
        tooltipPosition.x + 1 <= anchorPosition.x -> "左侧"
        else -> "重叠"
    }
}
