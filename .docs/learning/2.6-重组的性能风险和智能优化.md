# 2.6 重组的性能风险和智能优化、@Stable

> "重组就像一把双刃剑，用得好让UI如丝般顺滑，用不好就是性能杀手。今天我们就来学习如何驯服这头猛兽！" 🐯

## 概念介绍

重组(Recomposition)是Jetpack Compose的核心机制，它使UI能够自动响应状态变化。然而，过度重组会导致性能问题，而不充分的重组则可能导致UI不一致。

Compose提供了多种智能优化机制来平衡这一矛盾，包括智能跳过(Smart Skipping)、稳定性(Stability)
和结构相等性(Structural
Equality)检查。理解这些机制对于构建高性能的Compose应用至关重要。

本节将深入探讨重组的性能风险，Compose的智能优化策略，以及如何使用`@Stable`注解和其他技术来优化应用性能。

## 知识要点

- **重组的性能开销**：为什么重组可能成为性能瓶颈
- **智能跳过**：Compose如何避免不必要的重组
- **稳定性**：Compose的稳定性概念及其重要性
- **@Stable注解**：如何标记和实现稳定类型
- **@Immutable注解**：不可变类型的优化
- **key函数**：控制重组粒度的关键工具
- **避免重组陷阱**：常见的性能反模式及解决方案
- **性能分析工具**：如何检测和解决重组问题

```kotlin
fun RecompositionDemo() {

    Log.d("Compose", "RecompositionDemo被重组")
```

### 使用key控制重组粒度

```kotlin
@Composable
fun KeyDemo() {
    var items by remember { mutableStateOf(listOf("Item 1", "Item 2", "Item 3")) }
    
    Column(modifier = Modifier.padding(16.dp)) {
        // 添加按钮
        Button(
            onClick = {
                items = items + "Item ${items.size + 1}"
            },
            modifier = Modifier.align(Alignment.End)
        ) {
            Text("添加项目")
        }
        
        Spacer(modifier = Modifier.height(16.dp))
        
        Text("不使用key（可能导致状态混乱）:")
        
        // 不使用key的列表
        Column {
            items.forEach { item ->
                ItemWithState(item)
            }
        }
        
        Spacer(modifier = Modifier.height(24.dp))
        
        Text("使用key（保持状态一致）:")
        
        // 使用key的列表
        Column {
            items.forEach { item ->
                key(item) {  // 使用key确保正确的重组行为
                    ItemWithState(item)
                }
            }
        }
    }
}

@Composable
fun ItemWithState(name: String) {
    // 每个项目有自己的状态
    var isSelected by remember { mutableStateOf(false) }
    
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(vertical = 4.dp)
            .background(
                if (isSelected) Color.LightGray else Color.Transparent,
                shape = RoundedCornerShape(4.dp)
            )
            .clickable { isSelected = !isSelected }
            .padding(8.dp),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Text(
            text = name,
            modifier = Modifier.weight(1f)
        )
        
        Text(
            text = if (isSelected) "已选择" else "未选择",
            color = if (isSelected) Color.Blue else Color.Gray
        )
    }
}
```

## 进阶用法

### @Stable注解的使用

```kotlin
// 使用@Stable注解标记稳定类型
@Stable
class StableViewModel {
    // 内部使用MutableState
    private val _counter = mutableStateOf(0)
    val counter: State<Int> = _counter
    
    private val _name = mutableStateOf("User")
    val name: State<String> = _name
    
    // 提供修改方法
    fun incrementCounter() {
        _counter.value++
    }
    
    fun updateName(newName: String) {
        _name.value = newName
    }
}

@Composable
fun StableAnnotationDemo() {
    // 创建稳定类型实例
    val viewModel = remember { StableViewModel() }
    
    // 从稳定类型中读取状态
    val counter = viewModel.counter.value
    val name = viewModel.name.value
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "名称: $name",
            style = MaterialTheme.typography.headlineMedium
        )
        
        Text(
            text = "计数: $counter",
            style = MaterialTheme.typography.headlineSmall
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        Row(
            modifier = Modifier.fillMaxWidth(),
            horizontalArrangement = Arrangement.SpaceEvenly
        ) {
            Button(onClick = { viewModel.incrementCounter() }) {
                Text("增加计数")
            }
            
            Button(onClick = { viewModel.updateName("User ${counter + 1}") }) {
                Text("更新名称")
            }
        }
        
        Spacer(modifier = Modifier.height(32.dp))
        
        // 演示稳定性的好处
        Text(
            text = "以下组件只依赖counter，不依赖name",
            style = MaterialTheme.typography.bodyLarge
        )
        
        Spacer(modifier = Modifier.height(8.dp))
        
        // 这个组件只依赖counter，当只有name变化时不会重组
        CounterOnlyComponent(counter)
    }
}

    ) {
        Column(modifier = Modifier.padding(16.dp)) {

            )
            
            Text(
                text = "此组件已重组 ${recomposeCount.value} 次",
                style = MaterialTheme.typography.bodySmall,
                color = Color.Gray
            )
        }
    }
}
```

### 避免重组陷阱

```kotlin
@Composable
fun RecompositionTrapsDemo() {
    var counter by remember { mutableStateOf(0) }
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "重组陷阱示例",
            style = MaterialTheme.typography.headlineMedium
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 陷阱1：在Composable中创建对象
        BadPractice(counter)
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 陷阱2：在Composable中创建lambda
        BadPracticeLambda(counter)
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 良好实践：使用remember
        GoodPractice(counter)
        
        Spacer(modifier = Modifier.height(16.dp))
        
        Button(onClick = { counter++ }) {
            Text("增加计数")
        }
    }
}

@Composable
fun BadPractice(counter: Int) {
    // 不好的做法：每次重组都创建新对象
    val formatter = SimpleDateFormat("HH:mm:ss", Locale.getDefault())
    
    Text(
        text = "当前时间: ${formatter.format(Date())} (计数: $counter)",
        style = MaterialTheme.typography.bodyLarge
    )
}

@Composable
fun BadPracticeLambda(counter: Int) {
    // 不好的做法：每次重组都创建新lambda
    Button(
        onClick = {
            // 这个lambda在每次重组时都会创建新实例
            Log.d("Compose", "按钮被点击，计数: $counter")
        }
    ) {
        Text("点击我 (不好的做法)")
    }
}

@Composable
fun GoodPractice(counter: Int) {
    // 好的做法：使用remember缓存对象
    val formatter = remember { SimpleDateFormat("HH:mm:ss", Locale.getDefault()) }
    
    // 好的做法：使用remember缓存lambda，并指定依赖
    val onClick = remember(counter) {
        {
            Log.d("Compose", "按钮被点击，计数: $counter")
        }
    }
    
    Column {
        Text(
            text = "当前时间: ${formatter.format(Date())} (计数: $counter)",
            style = MaterialTheme.typography.bodyLarge
        )
        
        Spacer(modifier = Modifier.height(8.dp))
        
        Button(onClick = onClick) {
            Text("点击我 (好的做法)")
        }
    }
}
```

## 常见问题

### 1. 什么是重组的智能跳过机制？

**答**：智能跳过(Smart Skipping)是Compose的一项核心优化，它允许Compose在状态变化时只重组真正受影响的部分，而跳过不受影响的部分。

这一机制基于以下原则：

- 如果一个Composable函数的所有参数都没有变化，那么它可能会被跳过
- 参数变化的判断基于结构相等性(equals())，而不是引用相等性(===)
- 只有稳定类型的参数才能被可靠地用于跳过决策

智能跳过大大提高了Compose的性能，减少了不必要的UI更新。然而，它依赖于正确的稳定性信息，这就是为什么理解和正确使用
`@Stable`和
`@Immutable`注解如此重要。

### 2. @Stable和@Immutable注解有什么区别？

**答**：这两个注解都用于向Compose提供类型稳定性信息，但它们的含义不同：

- **@Stable**：表示一个类型是"稳定的"，意味着：
    1. 对象的equals()方法在其可观察属性不变的情况下返回一致的结果
    2. 可观察属性的变化可以被Compose检测到（通常通过State接口）
    3. 允许对象内部状态变化，但变化必须可观察

- **@Immutable**：表示一个类型是"不可变的"，意味着：
    1. 对象一旦创建，其所有可观察属性永远不会改变
    2. 对象的equals()方法永远返回一致的结果
    3. 比@Stable提供更强的保证，允许更激进的优化

简单来说，@Immutable是@Stable的特例，提供更强的不变性保证。不可变类型（如data
class）通常应该使用@Immutable，而包含可变但可观察状态的类型（如ViewModel）应该使用@Stable。

### 3. 如何识别和解决重组性能问题？

**答**：识别和解决重组性能问题的步骤：

1. **识别问题**：
    - 使用Layout Inspector的Recomposition Counts查看重组频率
    - 添加日志记录重组次数
    - 观察UI卡顿或电池消耗异常

2. **常见问题和解决方案**：
    - **过度重组**：使用remember缓存对象和lambda，确保正确的稳定性注解
    - **重组瀑布**：拆分大型Composable，使用key隔离重组范围
    - **昂贵计算**：使用remember或derivedStateOf缓存计算结果
    - **不必要的对象创建**：避免在Composable函数体中创建对象，使用remember
    - **lambda捕获**：使用remember(key)缓存lambda，明确指定依赖

3. **最佳实践**：
    - 保持Composable函数小而专注
    - 正确使用稳定性注解
    - 使用不可变数据结构
    - 避免在Composable中执行副作用
    - 使用适当的状态管理策略

### 4. 为什么需要使用key函数？

**答**：`key`函数在Compose中有两个主要用途：

1. **保持状态一致性**：当在循环中使用Composable时，key确保每个项目的状态与正确的数据项关联。没有key，Compose只能基于位置跟踪项目，这可能导致状态混乱。

2. **控制重组边界**：key创建一个新的重组作用域，可以防止重组"传染"到不相关的UI部分。这对于隔离昂贵的UI部分特别有用。

使用key的最佳实践：

- 在列表项中，使用稳定且唯一的标识符作为key
- 避免使用索引作为key，除非列表永远不会重新排序
- 当需要隔离重组时，可以使用Unit或其他常量作为key
