## 概念介绍

自定义Composable是Jetpack
Compose中最基本也最强大的能力之一。简单来说，自定义Composable就是创建你自己的可复用UI组件，它可以封装特定的UI结构、行为和状态管理逻辑。

在Compose中，任何标有`@Composable`
注解的函数都是一个Composable函数，可以在其他Composable函数中调用。通过组合这些函数，我们可以构建出从简单到复杂的各种UI组件，实现代码复用和关注点分离。

## 知识要点

- **@Composable注解**：定义Composable函数的必要标记
- **组合模式**：如何组合多个Composable构建复杂UI
- **参数传递**：向自定义Composable传递数据和回调
- **默认参数**：使用默认参数提高组件灵活性
- **状态管理**：在自定义Composable中处理状态
- **修饰符传递**：正确处理和传递Modifier
- **预览注解**：使用@Preview快速预览自定义组件

## 基础代码示例

### 创建简单的自定义Composable

```kotlin
@Composable
fun SimpleGreeting(name: String) {
    Text(text = "Hello, $name!")
}

// 使用自定义Composable
@Composable
fun GreetingScreen() {
    Column {
        SimpleGreeting(name = "Alice")
        SimpleGreeting(name = "Bob")
        SimpleGreeting(name = "Charlie")
    }
}
```

### 带修饰符的自定义Composable

```kotlin
@Composable
fun StyledGreeting(
    name: String,
    modifier: Modifier = Modifier  // 默认提供空的Modifier
) {
    Text(
        text = "Hello, $name!",
        fontSize = 20.sp,
        fontWeight = FontWeight.Bold,
        color = Color.Blue,
        modifier = modifier  // 应用传入的修饰符
    )
}

// 使用带修饰符的自定义Composable
@Composable
fun StyledGreetingScreen() {
    Column(
        modifier = Modifier.padding(16.dp)
    ) {
        StyledGreeting(
            name = "Alice",
            modifier = Modifier
                .padding(8.dp)
                .background(Color.LightGray, RoundedCornerShape(4.dp))
                .padding(16.dp)
        )
        
        Spacer(modifier = Modifier.height(8.dp))
        
        StyledGreeting(
            name = "Bob",
            modifier = Modifier
                .fillMaxWidth()
                .border(2.dp, Color.Red, RoundedCornerShape(8.dp))
                .padding(16.dp)
        )
    }
}
```

### 带回调的自定义Composable

```kotlin
@Composable
fun ClickableGreeting(
    name: String,
    onClick: () -> Unit,  // 点击回调
    modifier: Modifier = Modifier
) {
    Box(
        modifier = modifier
            .clip(RoundedCornerShape(4.dp))
            .background(Color.LightGray)
            .clickable(onClick = onClick)  // 应用点击回调
            .padding(16.dp)
    ) {
        Text(text = "Hello, $name! (Click me)")
    }
}

// 使用带回调的自定义Composable
@Composable
fun ClickableGreetingScreen() {
    Column(
        modifier = Modifier.padding(16.dp)
    ) {
        ClickableGreeting(
            name = "Alice",
            onClick = { Log.d("Greeting", "Alice was clicked") }
        )
        
        Spacer(modifier = Modifier.height(8.dp))
        
        // 使用remember记住点击次数状态
        var clickCount by remember { mutableStateOf(0) }
        
        ClickableGreeting(
            name = "Bob",
            onClick = { clickCount++ }
        )
        
        Text(text = "Bob was clicked $clickCount times")
    }
}
```

## 进阶用法

### 带内部状态的自定义Composable

```kotlin
@Composable
fun ExpandableCard(
    title: String,
    content: String,
    modifier: Modifier = Modifier
) {
    // 内部状态：是否展开
    var expanded by remember { mutableStateOf(false) }
    
    Card(
        modifier = modifier
            .fillMaxWidth()
            .animateContentSize(),  // 添加展开/收起动画
        elevation = CardDefaults.cardElevation(4.dp)
    ) {
        Column(
            modifier = Modifier.padding(16.dp)
        ) {
            Row(
                modifier = Modifier.fillMaxWidth(),
                horizontalArrangement = Arrangement.SpaceBetween,
                verticalAlignment = Alignment.CenterVertically
            ) {
                Text(
                    text = title,
                    style = MaterialTheme.typography.titleLarge
                )
                
                IconButton(onClick = { expanded = !expanded }) {
                    Icon(
                        imageVector = if (expanded) Icons.Default.KeyboardArrowUp else Icons.Default.KeyboardArrowDown,
                        contentDescription = if (expanded) "收起" else "展开"
                    )
                }
            }
            
            if (expanded) {
                Spacer(modifier = Modifier.height(8.dp))
                Text(text = content)
            }
        }
    }
}

// 使用带内部状态的自定义Composable
@Composable
fun ExpandableCardScreen() {
    Column(
        modifier = Modifier
            .padding(16.dp)
            .verticalScroll(rememberScrollState())

        ExpandableCard(
            title = "什么是Jetpack Compose?",
            content = "Jetpack Compose是Android现代UI工具包，使用声明式API简化UI开发..."
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        ExpandableCard(
            title = "声明式UI的优势",
            content = "声明式UI简化了状态管理，减少了模板代码，提高了开发效率..."

        Spacer(modifier = Modifier.height(16.dp))

            title = "Compose与传统View的区别",

    }
}
```

### 使用CompositionLocal传递数据

```kotlin
// 定义CompositionLocal
private val LocalUserName = compositionLocalOf { "Guest" }

@Composable
fun UserNameProvider(
    userName: String,
    content: @Composable () -> Unit
) {
    CompositionLocalProvider(LocalUserName provides userName) {
        content()
    }
}

@Composable
fun UserGreeting(modifier: Modifier = Modifier) {
    // 从CompositionLocal获取用户名
    val userName = LocalUserName.current
    
    Text(
        text = "Welcome back, $userName!",
        modifier = modifier,
        style = MaterialTheme.typography.headlineMedium
    )
}

// 使用CompositionLocal的示例
@Composable
fun UserProfileScreen() {
    UserNameProvider(userName = "John Doe") {
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(16.dp),
            horizontalAlignment = Alignment.CenterHorizontally
        ) {
            UserGreeting()
            
            Spacer(modifier = Modifier.height(16.dp))
            
            Text(text = "Your account settings")
            
            // 其他使用LocalUserName的组件...
        }
    }
}
```

## 常见问题

### 1. 什么时候应该创建自定义Composable？

**答**：以下情况适合创建自定义Composable：

- 当UI结构需要在多个地方复用时
- 当一组UI元素总是一起出现并具有相同的行为时
- 当需要封装特定的UI逻辑和状态管理时
- 当需要提高代码可读性，将复杂UI分解为更小的部分时

一般来说，遵循单一职责原则：每个Composable应该只做一件事，并做好这件事。

### 2. 如何正确处理Modifier参数？

**答**：处理Modifier的最佳实践：

- 总是将`modifier: Modifier = Modifier`作为自定义Composable的参数
- 将参数放在参数列表的最前面（仅次于必要的数据参数）
- 提供默认值`Modifier`，使调用者可以选择是否传入修饰符
- 将传入的modifier应用到自定义Composable的根元素上
- 不要在内部修改传入的modifier，除非有特殊需求

这样可以确保你的自定义Composable能够灵活地集成到各种UI结构中。

### 3. 自定义Composable中的状态应该如何管理？

**答**：状态管理策略取决于组件的用途：

- **无状态Composable**：不包含内部状态，所有状态通过参数传入，适合高度可复用的组件
- **有状态Composable**：包含内部状态，使用更简单，但灵活性较低
- **状态提升**：将状态提升到调用者，通过参数和回调传递，增加灵活性

一般建议优先创建无状态Composable，然后根据需要创建有状态的包装器。这样可以提供最大的灵活性和可复用性。

### 4. 如何测试自定义Composable？

**答**：测试自定义Composable的方法：

- 使用`@Preview`注解快速预览UI外观
- 使用Compose测试库编写单元测试
- 测试无状态Composable更容易，因为可以通过参数控制所有行为
- 对于有状态Composable，测试其状态变化和UI反应
- 使用语义树（Semantics Tree）测试可访问性和交互行为
