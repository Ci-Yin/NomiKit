# 2.7 derivedStateOf()——和 remember() 有什么区别？

## 概念介绍

在Jetpack Compose中，`remember()`和`derivedStateOf()`都是用于优化性能的重要函数，但它们的用途和工作原理有着根本区别。

`remember()`用于在重组过程中保留值，避免每次重组都重新创建对象或计算结果。它可以接受可选的键参数，当这些键变化时才重新计算值。

`derivedStateOf()`则用于创建一个派生状态，这个状态依赖于其他状态，但只有当计算结果真正变化时才会触发重组。它特别适合于从现有状态计算出新状态的场景，可以避免不必要的重组。

理解这两个函数的区别和正确使用场景，对于构建高性能的Compose应用至关重要。

## 知识要点

- **remember()的基本用法**：缓存对象和计算结果
- **remember()的键参数**：控制何时重新计算
- **derivedStateOf()的工作原理**：创建派生状态
- **结果变化vs依赖变化**：两者触发重新计算的不同条件
- **性能优化**：如何选择正确的函数降低重组成本
- **组合使用**：remember和derivedStateOf的协同工作
- **常见使用场景**：何时使用哪个函数
- **避免常见错误**：使用这两个函数的陷阱

## 基础代码示例

### remember()基本用法

```kotlin
@Composable
fun RememberBasicExample() {
    // 创建并记住一个状态
    var counter by remember { mutableStateOf(0) }
    
    // 记住一个昂贵的计算结果
    val formattedCounter = remember {
        // 假设这是一个昂贵的格式化操作
        "计数: $counter"
    }
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = formattedCounter,
            style = MaterialTheme.typography.headlineMedium
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        Button(onClick = { counter++ }) {
            Text("增加")
        }
        
        // 问题：formattedCounter不会随counter更新！
        // 因为它只在初始组合时计算一次
    }
}
```

### remember()和derivedStateOf()的区别

```kotlin
@Composable
fun ComparisonExample() {
    // 创建两个基础状态
    var firstName by remember { mutableStateOf("John") }
    var lastName by remember { mutableStateOf("Doe") }
    
    // 使用remember(key1, key2, ...)
    val fullName1 = remember(firstName, lastName) {
        "$firstName $lastName"
    }
    
    // 使用derivedStateOf
    val fullName2 by remember {
        derivedStateOf {
            "$firstName $lastName"
        }
    }
    
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "使用remember(key1, key2, ...):",
            style = MaterialTheme.typography.titleMedium
        )
        Text(text = fullName1)
        
        Spacer(modifier = Modifier.height(16.dp))
        
        Text(
            text = "使用derivedStateOf:",
            style = MaterialTheme.typography.titleMedium
        )
        Text(text = fullName2)
        
        Spacer(modifier = Modifier.height(24.dp))
        
        Row(
            modifier = Modifier.fillMaxWidth(),
            horizontalArrangement = Arrangement.SpaceEvenly
        ) {
            Button(onClick = { firstName = "Jane" }) {
                Text("修改名")
            }
            
            Button(onClick = { lastName = "Smith" }) {
                Text("修改姓")
            }
        }
        
        // 两种方法在这个简单例子中效果相同
        // 但在更复杂的场景中会有差异
    }
}
```

## 进阶用法

### 列表过滤示例：对比两种方法

```kotlin
@Composable
fun ListFilteringExample() {
    // 创建一个项目列表
    val allItems = remember {
        List(100) { "Item ${it + 1}" }
    }
    
    // 创建过滤文本状态
    var filterText by remember { mutableStateOf("") }
    
    // 方法1：使用remember(filterText)
    // 每当filterText变化，都会重新过滤整个列表
    val filteredItems1 = remember(filterText) {
        if (filterText.isEmpty()) {
            allItems
        } else {
            allItems.filter { it.contains(filterText, ignoreCase = true) }
        }
    }
    
    // 方法2：使用derivedStateOf
    // 只有当过滤结果真正变化时，才会触发使用此状态的UI重组
    val filteredItems2 by remember {
        derivedStateOf {
            if (filterText.isEmpty()) {
                allItems
            } else {
                allItems.filter { it.contains(filterText, ignoreCase = true) }
            }
        }
    }
    
    Column(modifier = Modifier.padding(16.dp)) {
        // 搜索框
        OutlinedTextField(
            value = filterText,
            onValueChange = { filterText = it },
            label = { Text("过滤项目") },
            modifier = Modifier.fillMaxWidth()
        )
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 选择使用哪种过滤方法
        var useMethod2 by remember { mutableStateOf(true) }
        
        Row(
            verticalAlignment = Alignment.CenterVertically,
            modifier = Modifier.padding(bottom = 8.dp)
        ) {
            Checkbox(
                checked = useMethod2,
                onCheckedChange = { useMethod2 = it }
            )
            
            Text(
                text = if (useMethod2) "使用derivedStateOf" else "使用remember(key)",
                modifier = Modifier.padding(start = 8.dp)
            )
        }
        
        // 显示过滤后的项目数量
        val filteredItems = if (useMethod2) filteredItems2 else filteredItems1
        Text(
            text = "显示 ${filteredItems.size} / ${allItems.size} 个项目",
            style = MaterialTheme.typography.bodyMedium,
            modifier = Modifier.padding(bottom = 8.dp)
        )
        
        // 显示过滤后的列表
        LazyColumn {
            items(filteredItems) { item ->
                Text(
                    text = item,
                    modifier = Modifier
                        .fillMaxWidth()
                        .padding(vertical = 4.dp)
                )
            }
        }
    }
}
```

### 复杂状态派生：排序和分组

```kotlin
// 数据类
data class Task(
    val id: String,
    val title: String,
    val isCompleted: Boolean,
    val priority: Int,  // 1-高, 2-中, 3-低
    val dueDate: Long?  // 毫秒时间戳
)

@Composable
fun ComplexDerivedStateExample() {
    // 基础任务列表
    val tasks = remember {
        mutableStateListOf(
            Task("1", "完成报告", false, 1, System.currentTimeMillis() + 86400000),
            Task("2", "回复邮件", false, 2, System.currentTimeMillis() + 172800000),
            Task("3", "准备会议", false, 1, System.currentTimeMillis() + 259200000),
            Task("4", "购买办公用品", false, 3, null),
            Task("5", "整理文档", false, 2, System.currentTimeMillis() + 432000000)
        )
    }
    
    // 排序和过滤选项
    var sortOption by remember { mutableStateOf("priority") }  // priority, dueDate
    var showCompleted by remember { mutableStateOf(true) }
    
    // 使用derivedStateOf处理复杂的排序和过滤逻辑
    val processedTasks by remember {
        derivedStateOf {
            // 首先过滤
            val filtered = if (showCompleted) {
                tasks
            } else {
                tasks.filter { !it.isCompleted }
            }
            
            // 然后排序
            when (sortOption) {
                "priority" -> filtered.sortedBy { it.priority }
                "dueDate" -> filtered.sortedWith(
                    compareBy<Task> { it.dueDate == null }
                        .thenBy { it.dueDate ?: Long.MAX_VALUE }
                )
                else -> filtered
            }
        }
    }
    
    // 使用derivedStateOf进行分组
    val groupedTasks by remember {
        derivedStateOf {
            processedTasks.groupBy { task ->
                when (task.priority) {
                    1 -> "高优先级"
                    2 -> "中优先级"
                    else -> "低优先级"
                }
            }
        }
    }
    
    Column(modifier = Modifier.padding(16.dp)) {
        // 控制选项
        Row(
            modifier = Modifier.fillMaxWidth(),
            horizontalArrangement = Arrangement.SpaceBetween
        ) {
            // 排序选项
            Column {
                Text("排序方式:", style = MaterialTheme.typography.bodyMedium)
                Row(verticalAlignment = Alignment.CenterVertically) {
                    RadioButton(
                        selected = sortOption == "priority",
                        onClick = { sortOption = "priority" }
                    )
                    Text("按优先级", modifier = Modifier.padding(start = 4.dp))
                }
                Row(verticalAlignment = Alignment.CenterVertically) {
                    RadioButton(
                        selected = sortOption == "dueDate",
                        onClick = { sortOption = "dueDate" }
                    )
                    Text("按截止日期", modifier = Modifier.padding(start = 4.dp))
                }
            }
            
            // 显示已完成选项
            Row(verticalAlignment = Alignment.CenterVertically) {
                Checkbox(
                    checked = showCompleted,
                    onCheckedChange = { showCompleted = it }
                )
                Text("显示已完成", modifier = Modifier.padding(start = 4.dp))
            }
        }
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 添加任务按钮
        Button(
            onClick = {
                val newId = (tasks.size + 1).toString()
                tasks.add(
                    Task(
                        id = newId,
                        title = "新任务 $newId",
                        isCompleted = false,
                        priority = (1..3).random(),
                        dueDate = if (Random.nextBoolean()) 
                            System.currentTimeMillis() + Random.nextLong(86400000, 604800000) 
                        else 
                            null
                    )
                )
            },
            modifier = Modifier.align(Alignment.End)
        ) {
            Text("添加任务")
        }
        
        Spacer(modifier = Modifier.height(16.dp))
        
        // 显示分组任务
        LazyColumn {
            groupedTasks.forEach { (group, tasksInGroup) ->
                // 组标题
                stickyHeader {
                    Text(
                        text = group,
                        style = MaterialTheme.typography.titleMedium,
                        color = Color.White,
                        modifier = Modifier
                            .fillMaxWidth()
                            .background(MaterialTheme.colorScheme.primary)
                            .padding(8.dp)
                    )
                }
                
                // 组内任务
                items(tasksInGroup, key = { it.id }) { task ->
                    TaskItem(
                        task = task,
                        onToggleCompleted = { taskId ->
                            val index = tasks.indexOfFirst { it.id == taskId }
                            if (index >= 0) {
                                tasks[index] = tasks[index].copy(isCompleted = !tasks[index].isCompleted)
                            }
                        }
                    )
                }
            }
        }
    }
}

@Composable
fun TaskItem(
    task: Task,
    onToggleCompleted: (String) -> Unit
) {
    val dateFormatter = remember { SimpleDateFormat("yyyy-MM-dd", Locale.getDefault()) }
    
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(vertical = 4.dp, horizontal = 8.dp),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Checkbox(
            checked = task.isCompleted,
            onCheckedChange = { onToggleCompleted(task.id) }
        )
        
        Column(
            modifier = Modifier
                .weight(1f)
                .padding(start = 8.dp)
        ) {
            Text(
                text = task.title,
                style = if (task.isCompleted) 
                    TextStyle(textDecoration = TextDecoration.LineThrough)
                else
                    LocalTextStyle.current
            )
            
            task.dueDate?.let { dueDate ->
                Text(
                    text = "截止日期: ${dateFormatter.format(Date(dueDate))}",
                    style = MaterialTheme.typography.bodySmall,
                    color = Color.Gray
                )
            }
        }
    }
}
```

## 常见问题

### 1. 什么时候应该使用remember()，什么时候应该使用derivedStateOf()？

**答**：选择取决于你的具体需求：

- **使用remember()**：
    - 当你需要在重组过程中保留一个值或对象
    - 当你需要基于特定键（参数）的变化重新计算值
    - 当计算结果不是状态，或者不需要被观察

- **使用derivedStateOf()**：
    - 当你需要从其他状态派生一个新状态
    - 当你希望只在计算结果真正变化时才触发重组
    - 当你处理的是昂贵的计算，特别是列表过滤、排序等操作
    - 当多个状态共同决定一个派生状态

简单来说，如果你只是想缓存一个值，使用`remember()`；如果你需要创建一个依赖于其他状态的新状态，并且希望优化重组，使用
`derivedStateOf()`。

### 2. remember(key)和derivedStateOf()有什么性能差异？

**答**：两者的性能差异主要体现在重组触发的条件上：

- **remember(key)**：当任何一个键变化时，都会重新计算值，无论计算结果是否变化。例如，如果你过滤一个列表，即使过滤结果相同，只要过滤条件变化，就会重新计算。

- **derivedStateOf()**：只有当计算结果真正变化时，才会触发使用该状态的UI重组。例如，如果你修改了过滤条件，但过滤后的列表没有变化，那么使用这个列表的UI不会重组。

在处理大型集合或昂贵计算时，`derivedStateOf()`
通常能提供更好的性能，因为它减少了不必要的重组。但它也有轻微的运行时开销，因为需要比较计算结果。对于简单场景，两者性能差异可能不明显。

### 3. 为什么我的derivedStateOf()没有正确更新？

**答**：如果你的`derivedStateOf()`没有正确更新，可能有以下几个原因：

1. **没有正确包装在remember中**：`derivedStateOf()`应该包装在`remember {}`中，否则每次重组都会创建新的派生状态。
   ```kotlin
   // 正确用法
   val derived by remember { derivedStateOf { /* 计算 */ } }
   
   // 错误用法
   val derived by derivedStateOf { /* 计算 */ }
   ```

2. **依赖的状态不可观察**：确保`derivedStateOf()`内部使用的所有状态都是可观察的（如`MutableState`）。
   ```kotlin
   // 可观察状态
   var counter by remember { mutableStateOf(0) }
   
   // 不可观察变量
   var counter = 0  // 这个变化不会触发derivedStateOf更新
   ```

3. **使用了不稳定类型**：确保依赖的类型是稳定的，或者使用`@Stable`注解标记。

4. **忘记使用by关键字**：使用`derivedStateOf()`时，通常应该使用`by`关键字进行委托。
   ```kotlin
   // 正确用法
   val derived by remember { derivedStateOf { /* 计算 */ } }
   
   // 不使用by时需要.value
   val derived = remember { derivedStateOf { /* 计算 */ } }
   Text(derived.value)  // 需要.value
   ```

### 4. remember()和derivedStateOf()可以组合使用吗？

**答**：是的，`remember()`和`derivedStateOf()`可以组合使用，这在某些场景下非常有用：

1. **基本组合**：使用`remember`保存`derivedStateOf`的实例。
   ```kotlin
   val derived by remember { derivedStateOf { /* 计算 */ } }
   ```

2. **带键的组合**：当派生状态依赖于某些不是状态的参数时。
   ```kotlin
   val derived by remember(param1, param2) { 
       derivedStateOf { 
           // 使用param1, param2和其他状态计算
       } 
   }
   ```

这种组合使用可以在保留`derivedStateOf()`优化重组的好处的同时，根据特定参数重新创建派生状态。
