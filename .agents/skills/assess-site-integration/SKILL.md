# 网站接入条件评估

## 目的与边界

本 skill 用于在新增具体站点解析器前，判断目标网站是否满足既定产品范围和 NomiKit 现有模型的接入条件。

- 只做只读调研、证据整理和接入判断，不因评估请求自动创建或修改 parser、模型、UI、测试或构建配置。
- “页面能打开”“HTTP 200”“有分页控件”“能拿到封面”都不是单独的接入通过条件。
- 必须先明确目标范围：例如原始图片下载、作品目录预览、完整章节阅读、视频播放或仅搜索发现。评估结论只针对该范围。
- 若用户只要求目录预览，不得擅自把“原始文件可下载”加入硬性条件；若用户要求原始资源，则预览图、封面、播放页或内容包不能替代原始资源。
- 需要实现时，另行加载 `feature-parser` 或 `feature-parser-site` skill，并等待用户明确要求；本 skill
  的结论不等于实现授权。

## 评估流程

### 1. 先定义必要条件

从用户目标、现有调用方和相关模型确认：

1. 目标内容是什么，以及结果如何被消费；
2. 必须支持哪些列表、搜索、详情和分页动作；
3. 资源必须是预览图、原图、可下载文件、可播放媒体还是外部客户端资源；
4. 目标平台是否为 Android、iOS、Desktop 或多平台；
5. 登录、API Key、Cookie、Steam/外部客户端等依赖是否被产品接受。

把必要条件与可选能力分开。排行榜、合集、作者信息、评分等可选能力不能弥补核心资源链路缺失。

### 2. 建立可复核证据

每项关键结论都记录：

- 采样时间和时区；
- 入口 URL、请求方法、查询参数、必要请求头和请求体结构；
- 是否匿名，是否需要登录、Cookie、API Key、签名或客户端；
- HTTP 状态、响应 MIME、关键字段和资源内容类型；
- 作品/帖子/章节的真实 ID，以及列表与详情是否对应。

证据必须标注来源等级：

- **实时验证**：实际发出的只读请求及其可复核响应；
- **官方文档**：官方接口或产品文档明确规定的行为；
- **历史资料**：旧报告、旧构建或第三方记录；
- **推测**：根据页面、代码或命名推断，不能作为通过依据；
- **未验证**：尚未取得足够证据。

不要记录 API Key、Cookie、登录令牌或其他秘密的具体值。浏览器成功只能说明该浏览器环境成功；还要验证计划采用的运行方式在目标平台可以复现。

### 3. 检查列表、搜索和详情

必须验证：

- 列表结果包含稳定、可解析的真实内容 ID；
- 搜索词、标签或筛选条件确实改变结果，并在后续分页中保持；
- 列表 ID 可以打开对应详情，详情没有被重定向到无关页面；
- 不把广告、推荐、推广位或页面其他区域的 ID 混入结果；
- 错误响应、空结果和缺少关键字段时能被识别，不能静默当作空成功。

若目标为图片或视频资源，还要从列表或详情继续验证到实际目标媒体，而不是停在作品页面。

### 4. 严格验证连续分页

分页是必要条件时，必须验证真实协议，而不是只看到 `page`、`p`、`offset`、`cursor` 参数或分页按钮。

- 页码分页：在相同查询条件下至少采样连续的 page 1、2、3；记录每页 ID 数量、相邻页交集和新增数量。
- 游标分页：验证首批返回的游标被原样用于下一批，并确认下一批 ID 与首批有新增且无异常重复。
- 验证末页、空页或明确的结束字段；未知总页数保持未知，不填充固定值。
- 真实动态榜单可能在不同时间发生排序漂移。固定夹具应验证准确分页；实时结果若有重叠，要分析新增数量、排序漂移和采样时间，不把所有重叠自动解释为正常，也不把一次重叠直接判定为分页不可能。
- 数据量不足三页时按实际规模验证最后一页和空结果，不为了满足形式强行请求不存在的页面。
- 不混用不同协议：官方 API 的 cursor 与匿名网页的 page 不能互相替代；浏览器内部 POST 未取得完整 body
  和必要 headers 时，不应把它作为唯一实现依据。

仅有以下证据时，分页仍属于“未验证”：HTTP 200、URL 中存在页码、页面显示第 2 页、接口签名包含
page/limit、或两次只比较了封面图片。

### 5. 验证目标资源真实性

根据目标范围，完成从列表/详情到实际资源的闭环验证：

- 读取实际资源 URL，确认响应 MIME、文件头或可解析/可播放内容；
- 区分缩略图、封面、预览图、原图、视频、流媒体、压缩包、场景包和外部客户端资源；
- 不能用预览图冒充原图，不能用作品标签分辨率冒充预览资源尺寸，不能用包体大小证明原始文件可取；
- 若返回的是内容包或订阅入口，必须明确记录“需要客户端/外部流程”，不能宣称已满足下载条件；
- 资源只在登录用户、地区、签名时效、Referer 或客户端会话下可取时，验证目标运行环境是否能稳定提供这些依赖；
- 对动态媒体，不能仅凭封面或页面存在播放器就宣称可以下载或播放。

### 6. 检查 NomiKit 适配边界

对照目标领域现有 API 和模型检查：

- 请求模型能否表达站点的列表、搜索、详情和分页协议；
- `pagination` 是否能准确表达 `page`、`totalPages`、`hasNext` 或 `nextCursor`；
- 结果模型是否能表达真实资源语义、媒体类型、分级和来源；
- 缺失字段是否应保持未知，而不是伪造 `0`、空扩展名、假 MD5、假原图或假子图；
- 现有消费方是否会把预览图当作可下载原图，或把外部客户端资源当作普通 URL；
- 站点协议是公开稳定 API、公开页面结构还是构建绑定的内部协议；改版、限流和错误变化是否可识别；
- 使用频率、授权条款、robots/服务限制和目标平台网络能力是否可接受。

如果现有模型无法准确表达核心结果，这属于接入缺口，不得用站点专属字段散落在通用模型或伪值掩盖。可以提出后续模型设计，但不能把它算作当前条件已满足。

## 结论规则

逐项给出“通过 / 不满足 / 未验证 / 不适用”，并附证据、影响和缺口。最终只允许使用以下结论之一：

### 满足接入条件

目标范围内的所有必要条件均有充分实时或官方证据，目标环境可以满足访问依赖，现有模型能够准确表达结果。该结论不表示已经实现、测试或上线。

### 暂不满足接入条件

至少一个必要条件已确认不满足，或已有明确不可接受的访问/资源依赖。说明恢复评估所需的具体变化，例如获得授权
API、打通原始资源链路、补充目标平台能力或改变产品范围。

### 证据不足，暂缓判断

关键条件尚未验证，但不能据此断言技术上不可行。列出最小补证动作，例如保存 page 1–3 的 ID 集合、验证详情资源
MIME、捕获完整请求参数或在目标平台复现匿名请求。

不得用“部分可用”“基本可行”替代上述结论，也不得用可选能力抵消必要条件的失败。替代方案必须单列，并明确说明它改变了原目标；未经用户确认不得把替代方案当作接入通过。

## 操作边界与停止条件

- 只进行必要的只读访问；不自动登录、订阅、购买、投票、收藏、评论、上传、安装客户端或执行未知写入动作。
- 小范围采样足以证明协议时停止，不批量抓取，不绕过权限、验证码、地区限制或访问控制。
- 连续失败或出现明确访问限制时记录环境差异和阻塞；不无限重试，也不通过代理、伪造身份或其他方式绕过限制。
- 临时证据优先放系统临时目录；任务结束清理本次生成的文件和浏览器标签。
- 调研结束后停止在报告，不自动修改仓库、生成 parser、创建测试或启动长期任务。

## 输出格式

报告按以下顺序，简洁但可复核：

1. **结论与目标范围**：明确三种最终结论之一，以及本次判定的产品范围；
2. **必要条件表**：条件、状态、证据等级、实际结果、缺口；
3. **请求与响应摘要**：列出关键只读请求、方法、参数、状态和关键字段；
4. **资源语义与项目兼容性**：说明预览/原图/媒体包/外部客户端的区别及模型影响；
5. **未验证事项与最小下一步**：只列恢复判断所需的最小补证动作；
6. **范围外替代方案**：只有存在时列出，并说明它改变了什么目标。

不要在报告中输出尚未请求的实现代码。若需要展示协议形状，只能给不含凭据的最小伪请求示例，例如：

```text
GET /workshop/browse?query=<固定条件>&page=2
验证：current_page、total_pages、results[].id、相邻页 ID 交集
```
