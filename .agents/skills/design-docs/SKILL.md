# 设计文档生命周期

让读者区分拟议设计与当前实现：设计文档保存背景、取舍、边界和实现导航；源码、构建配置与测试是行为依据。

## 范围与位置

- 长期方案放在 `.docs/design/`，沿用中文文件名和稳定路径；不因状态变化在“待实现/已实现”目录间搬迁。
- 文件名和标题默认不加版本号；仅当实际出现需独立维护的第二版时使用 `-v2` 等后缀，确需并列区分时再为第一版补
  `-v1`，同步标题、索引与入站引用。日常修订直接更新原文，不递增方案版本。
- 临时执行清单留在 `.plan/`；调研不自动视为已采纳方案。只处理本任务相关文档。
- 以文档头部为状态来源，在 [设计索引](<../../../.docs/design/README.md>) 同步简短摘要，不复制正文。
- 编写模块 README 时另读 [module-docs](<../module-docs/SKILL.md>)；没有模块 README
  时注明缺口，不默认扩展为整模块文档工程。

## 状态与证据

| 状态            | 判定                                                               |
|-----------------|--------------------------------------------------------------------|
| 草案            | 尚在讨论，未确认采用                                               |
| 待实现          | 已采纳但未落地                                                     |
| 实施中          | 已部分落地，列明剩余范围                                           |
| 已实现          | 约定范围已落地，正文已按实际实现整理；不代表无缺陷或所有平台已验证 |
| 已废弃 / 已替代 | 不再适用；替代时链接后继文档                                       |

- 状态必须与逐项核对结果一致；不能只因同名类存在或用户提到“做完了”就把全部目标视为已验收。
- 主要范围仍缺失时用“实施中”，不能删掉未完成目标来凑“已实现”；已落地功能的已知缺陷另列，不隐瞒。
- 实现状态、验证结果、发布状态分开。记录核对日期和源码基线；没有测试结果就写“未执行/未确认”。
- 尚未核对的旧文档，索引写“未标注（待核对）”，不凭标题推断为待实现，也不批量修改无关正文。

头部使用以下信息；值来自本次任务的实际证据，不为填写模板而编造：

```markdown
> 状态：草案 / 待实现 / 实施中 / 已实现 / 已废弃 / 已替代
> 范围：本版包含的能力与平台
> 相关模块：实际 Gradle project 与必要构建逻辑
> 最近核对：日期；源码提交或工作区基线（不是推测的完成日期）
> 验证记录：实际检查结果、未验证项及正文入口
```

## 创建与实施

- 说明背景、目标、非目标、关键决策及验收条件；涉及实现、接口或数据结构时提供必要的拟议代码示例，并明确尚非当前
  API。
- 引用已有能力而非重写现有设计。执行前按模块读取专用 skill、构建配置、入口和调用方。
- 实施中逐项记录已落地与剩余内容；有偏离时说明实际选择和原因。只确认到差异、未确认原因时如实标明。

## 转换为实现说明

1. 先读原文、工作树与文档历史，再核对目标对应的源码、生成器、调用方和测试。
2. 直接演进当前文档，不创建归档目录或原稿副本。历史追溯只引用实际存在的 Git
   记录；没有记录时如实说明，不声称原稿可恢复，也不擅自提交来制造历史。
3. 保留设计时背景、目标/非目标、取舍和稳定约束；将过时的“当前/建议新增”改为历史背景或实际结论。
4. 将接口、生成对象和算法的整段实现副本换成“职责 + 源码文件链接 +
   关键符号”。已实现设计文档不再内嵌实现代码示例；使用示范链接真实调用方、可编译样例或测试。
5. 迁移步骤收敛为实施结果；开放问题写已确认结论，未落地部分列剩余范围、已知限制或后续提案，不能直接删掉。
6. 记录原方案与实际实现的差异。当前缺陷、平台缺口和验证缺口不能以“已实现”掩盖；只整理文档，不借机修复代码。
7. 同步相关索引、入站引用及受影响的模块文档/skill；不复制完整教程，不自动重写所有相关文档。

按实际复杂度组织“背景与目标、核心决策、实现入口、差异与限制、验证记录、后续演进”，不强制空章节。

## 引用与验证

- 使用相对 Markdown 链接；稳定文件路径配符号名，不只依赖易漂移的行号。历史证据可补提交标识。
- 生成代码指向生成任务和源集装配，不链接本机 `build/` 产物；不存在的测试或 README 不造链接。
- 核对所有本地链接和关键结论。命令仅代表验证入口，运行后才可记录结果，并注明日期、环境/平台、成功、失败或未执行。
- 纯文档转换先做内容与链接检查；不为标状态启动全量构建。需要行为验证时选最窄任务，未执行的明确保留。
- 已实现功能的新扩展独立标注范围；重大变更另建后继方案，不让当前实现与未来设想混写。

交付时报告状态变化、实现依据、验证结果、剩余问题，以及有无可追溯的 Git 历史。
